# 一个搭子APP的后台服务
- 支持发布主题
- 发布主题后，同一个社区的用户可以收到这个主题，不同社区的用户不会受到该主题
- 发布的主题模型字段：标题内容，标题详情，邀请约束
- 注册后，性别，年龄都是可选的
- 接受了同一个主题邀请的，可以互相评价
# 评价模型
- 评价可给好，中，差评级
- 评价可以给分类，例如 失约，守信等等社交中的评价，帮我扩展下
- 系统可以针对用户进行自评价，【自评价算法单独描述】
- 仅有接受过同一主题的用户才可以进行评价
# 系统自动评级算法
- 如果一个用户的好评率很高，个别用户总是给其他用户打差评，系统则自动给这个用户加个恶意差评标签
# 主题模型
- 接受了主题的用户，则自动进入一个聊天室
- 聊天室支持保存历史的聊天记录
- 用户发布的主题可以设置约束：例如年龄，性别
# 用户模型
- 用户注册后，年龄，性别，头像是可选的，不要求用户必输
- 昵称，社区是必填的，一个用户7天内不可切换社区
- 支持邮箱，短信注册，注册需要输入验证码

# 编码规范
- 这是个app的服务端，还有个android客户端，用户所有的操作都在android的客户端上
- 所有的接口功能通过http返回
- 返回的格式用同一套模型，必须有错误码，错误描述，数据主体。数据主体每个接口各不相同，根据实际接口功能返回
- 所有请求都要记录日志，根据重要程度用不同的日志级别，http的请求用info的日志
- 服务端用python实现
- 数据库用postgresql，数据库的脚本支持幂等执行
- 启动，停止服务 都写一个start.sh， stop.sh 脚本
- 日志存放到 /var/service/log/{服务名称} 目录下
