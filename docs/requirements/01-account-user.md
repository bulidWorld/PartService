# 需求一：账号、注册与用户资料

## 1. 目标

让用户通过邮箱或手机号完成验证码注册/登录，并建立可用于匹配主题的基础资料。昵称和社区是必填信息，性别、年龄、头像可后补。

## 2. 业务规则

1. 注册方式为邮箱或短信验证码，验证码有效期、发送频率和错误次数由系统统一控制。
2. 同一个邮箱/手机号只能绑定一个有效账号；已注册身份再次验证后进入登录流程。
3. 昵称、社区必填；昵称需通过长度、敏感词和唯一性策略校验（唯一性是否全局或社区内，待产品确认）。
4. 年龄、性别、头像均可为空；用户可以在注册后补充或修改。
5. 用户 7 天内不可切换社区。切换成功后重新计算 7 天冷却时间。
6. 被封禁用户不能登录或进行发帖、邀请、聊天、评价等业务操作。

## 3. 注册主流程

1. 用户选择邮箱或手机号，输入身份信息。
2. 客户端请求发送验证码；系统校验格式、频率和风控规则后发送。
3. 用户输入验证码、昵称和社区，提交注册。
4. 系统校验验证码未过期、未消费且身份未被其他账号占用。
5. 系统创建用户和登录凭证，记录注册审计日志，返回 access token、refresh token 和用户资料。
6. 客户端进入主题首页；可提示用户完善年龄、性别和头像，但不得阻塞基本使用。

## 4. 登录与资料维护流程

- 登录：身份 + 验证码校验成功后签发 access token；刷新令牌用于续期。
- 修改资料：用户提交变更字段，服务端逐字段校验；昵称变更、头像变更记录审计日志。
- 切换社区：用户选择新社区 → 服务端检查社区有效、当前用户状态正常且距离上次切换已满 7 天 → 更新社区和切换时间 → 后续主题流按新社区计算。

## 5. 异常流程

| 场景 | 处理 |
| --- | --- |
| 验证码错误/过期 | 拒绝操作并提示重新获取；超过次数后验证码作废 |
| 发送过于频繁 | 返回限流提示和下次可发送时间 |
| 昵称不合法 | 返回字段级错误，不创建账号或不保存修改 |
| 7 天内切换社区 | 拒绝修改并返回剩余冷却时间 |
| 账号被封禁 | 拒绝登录，并提示联系客服/申诉入口 |

## 6. 验收标准

- 未填写昵称或社区不能完成注册。
- 不填写年龄、性别、头像仍可注册并浏览不要求这些条件的主题。
- 同一身份不能产生两个有效账号。
- 成功切换社区后 7 天内再次切换必定失败，跨 7 天后成功。
- access token 失效后可使用 refresh token 续期；注销后 refresh token 不可继续使用。
