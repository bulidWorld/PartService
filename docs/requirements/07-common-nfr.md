# 需求七：通用规则、非功能需求与待确认事项

## 1. 统一接口与错误处理

- 所有客户端操作通过 HTTP API 完成，响应统一包含错误码、错误描述、数据主体和 request_id。
- HTTP 状态码表达协议层结果，业务判断以业务错误码为准。
- 列表支持游标分页；创建邀请、接受邀请、发消息、提交评价必须幂等。
- 客户端收到未登录错误时可刷新 token 一次，失败后清理会话并回到登录页。

## 2. 日志与审计

- 所有 HTTP 请求以 INFO 记录，必须包含 request_id、路径、耗时、结果码和用户 ID（如已登录）。
- 注册、登录、社区切换、发帖、邀请、接受、评价、标签变化写审计日志。
- 验证码、access token、refresh token、评论中的敏感信息必须脱敏，不得写入普通日志。
- 日志目录为 `/var/service/log/{服务名称}`；日志需轮转并限制保留周期。

## 3. 服务与数据要求

- 服务端使用 Python，数据库使用 PostgreSQL。
- 数据库初始化/迁移脚本必须支持幂等执行；启动和停止分别提供 `start.sh`、`stop.sh`。
- 关键状态变更使用事务；异步任务必须可重试、可观测、可补偿。
- 所有时间统一 UTC；敏感数据最小化存储，验证码只存摘要。

## 4. 安全与隐私

- 全链路 HTTPS；认证凭证不得通过 URL 传输。
- 主题、聊天室、评价均按用户权限做服务端鉴权，不能只依赖客户端隐藏按钮。
- 头像和聊天附件使用受控存储 URL，并校验类型、大小和访问权限。
- 提供账号注销/数据保留策略；具体法规要求和保留期限需由产品与法务确认。

## 5. 待确认事项

1. 昵称是全局唯一还是社区内唯一？
    昵称不用去重校验，可重复
2. 主题是否支持非邀请用户主动报名？
    主题推送给所有满足要求的用户，用户可以选择接受或拒绝
3. 主题关闭后原参与者是否仍可发送消息？
    可以
4. 用户能否编辑、删除或申诉评价？管理员处理页面范围是什么？
    用户不能对评价做任何处理，可提交申诉，管理员暂时不做这个角色
5. 风险标签是否对本人、其他用户或仅运营人员可见？
    所有用户可见，风险标签应该叫系统评级更合适
6. 邮箱/短信供应商、验证码有效期、限流阈值和账号注销保留周期。
