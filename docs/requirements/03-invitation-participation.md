# 需求三：主题邀请与参与

## 1. 目标

让主题发布者邀请合适的社区用户，受邀用户明确接受或拒绝；接受后双方成为该主题参与者并自动进入聊天室。

## 2. 角色与权限

- 发布者：可邀请用户、查看邀请状态、关闭主题。
- 被邀请用户：可查看邀请详情、接受或拒绝。
- 已参与用户：可进入聊天室、在满足条件后互相评价。
- 非邀请用户：不能通过接口直接加入主题（是否支持公开报名，概览未定义，默认不支持）。

## 3. 邀请主流程

1. 发布者在主题内选择同社区且满足约束的用户，提交邀请。
2. 服务端校验发布者是主题 owner、主题仍开放、目标用户同社区且未被邀请/参与。
3. 创建 `待处理` 邀请，向目标用户产生站内通知或推送。
4. 目标用户打开邀请详情，查看主题摘要、发布者和约束。
5. 目标用户选择接受或拒绝；服务端在事务中更新邀请状态。
6. 接受成功时创建主题参与关系和聊天室成员关系，返回聊天室 ID。

## 4. 状态流转

```text
待处理 ──接受──> 已接受 ──(可选离开)──> 已退出
待处理 ──拒绝──> 已拒绝
待处理 ──主题过期/关闭──> 已失效
```

已接受邀请不可再次拒绝；重复接受/拒绝返回当前最终状态，不重复创建参与关系和聊天室成员。

## 5. 异常流程

- 目标用户已不满足主题约束：接受时重新校验，失败则提示资料或主题条件已变化。
- 主题已关闭/过期：不能新建邀请，也不能接受待处理邀请。
- 用户已被封禁或已离开社区：邀请失效。
- 发布者邀请自己、重复邀请同一用户、跨社区邀请：返回业务错误。

## 6. 验收标准

- 只有主题发布者能发出邀请。
- 接受邀请后用户立即出现在参与者列表和聊天室成员列表。
- 网络重试不会产生两条邀请、两个聊天室或两条参与关系。
- 非邀请用户无法通过修改请求参数加入主题。
