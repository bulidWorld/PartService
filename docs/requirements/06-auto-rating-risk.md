# 需求六：系统自动评级与风险标签

## 1. 目标

识别“自身获得评价较好，但持续给他人恶意差评”的异常评价行为，为用户增加风险提示标签，辅助用户判断和运营处置。

## 2. 数据与计算原则

1. 统计对象包括用户收到的好/中/差评价，以及用户发出的评价分布。
2. 默认按近 90 天滚动窗口计算；窗口、最小样本量和阈值必须配置化。
3. 样本不足时不打标签，避免新用户被少量评价误判。
4. 除评分外，可结合评价分类、评价时间集中度、被评价者的其他反馈差异等信号。
5. 算法结果必须保存算法版本、时间窗口、样本量、阈值和证据摘要，支持复核。

## 3. 计算流程

1. 评价写入后发送统计任务；定时任务定期补偿失败任务。
2. 聚合每个用户的收评和发评指标，生成统计快照。
3. 判断是否达到最小样本量和异常阈值。
4. 达到条件则创建/更新 `恶意差评` 风险标签；不再满足条件则标记为移除，不直接删除历史标签。
5. 用户资料和评价摘要接口返回当前有效标签；运营端可查看证据并人工移除。

## 4. 产品呈现与安全边界

- 标签是风险提示，不等同于违规事实，不应直接对用户展示未经设计的算法分数。
- 默认向用户展示“系统风险提示”及申诉入口，不展示其他用户的隐私评价细节。
- 算法不得自动删除评价、自动封禁账号；高风险处置需人工或独立风控流程确认。

## 5. 验收标准

- 少于最小样本量的用户不会被打标签。
- 同一批评价重复计算不会产生重复标签。
- 算法版本变化后可区分新旧结果并追溯证据。
- 统计任务失败可重试，最终结果不会因任务重复执行而膨胀计数。
