# 需求五：用户互相评价

## 1. 目标

只允许共同参与同一主题的发布者和已接受用户互相评价，通过好/中/差和具体分类沉淀可信的社交反馈。

## 2. 评价内容

- 评分：好、中、差，必选且只能选择一个。
- 分类：可多选，必须来自系统启用分类；建议包括守信、准时、沟通顺畅、友善、有帮助、一般、失约、迟到、恶意骚扰、言语攻击、不实信息。
- 文字评论：可选，需做长度、敏感词和隐私信息校验。
- 用户提交评价可匿名

## 3. 提交评价主流程

1. 用户在主题参与者列表中选择评价对象。
2. 服务端校验评价者和被评价者不是同一人，且双方在该主题均具备参与资格（发布者在首名其他用户接受时取得参与资格，其他用户在接受成功后取得）。
3. 校验该主题下不存在历史评价；存在则返回已评价状态。
4. 保存评分、分类和评论，记录审计日志。
5. 异步更新被评价者统计，并触发自动评级算法。
6. 返回提交结果；客户端可立即显示“已评价”，统计数值以后端刷新结果为准。

## 4. 评价可见性与限制

- 评价只能关联一个主题，不能跨主题评价。
- 用户可查看自己的评价汇总和公开评价明细；不展示联系方式等敏感资料。
- 默认不允许用户自行删除或修改评价，申诉/管理员处理流程待确认。
- 主题未实际产生共同参与关系时，即使两人同社区也不能评价。

## 5. 异常流程与验收

- 除发布者外，未接受主题、只查看过主题、仅在同一聊天室但未具备参与资格的用户不能评价。
- 重复点击提交只产生一条评价。
- 已禁用的分类不能被提交；客户端缓存旧分类时服务端拒绝并要求刷新。
- 评价统计中的好评率在无样本时显示“暂无评价”，不显示为 0%。
