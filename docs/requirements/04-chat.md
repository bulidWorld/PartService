# 需求四：聊天室与消息

## 1. 目标

为同一主题的参与者提供自动创建的聊天室，并支持消息发送、历史记录、已读和撤回。

## 2. 进入聊天室规则

1. 发布主题时不创建聊天室；首名其他用户接受主题时自动创建唯一聊天室，发布者成为 owner 并自动加入。
2. 接收推送的用户只有在接受主题成功后成为 member；首名接受者与发布者一起加入，后续接受者加入同一聊天室。
3. 非参与者访问聊天室必须被拒绝；退出主题或被移除后不能发送新消息。
4. 主题关闭后保留历史消息，允许原成员继续发送消息，禁止新成员加入。

## 3. 发消息主流程

1. 客户端提交消息类型、内容和客户端消息 ID。
2. 服务端校验成员身份、消息长度/附件元数据和聊天室状态。
3. 以客户端消息 ID 做幂等处理：首次写入并广播，重复请求返回原消息。
4. 更新聊天室最后消息时间，向其他在线成员推送。
5. 离线成员下次进入时通过历史接口补齐消息。

## 4. 已读与撤回

- 用户只能撤回自己发送的消息；撤回后保留消息记录，客户端显示“消息已撤回”。
- 图片等附件只保存受控 URL 和元数据，不在消息正文中保存未经校验的外部地址。

## 5. 异常流程与验收

- 非成员读取、发送、标记已读、撤回均返回无权限。
- 空消息、超长消息、未知消息类型必须拒绝。
- 断网重试不会产生重复消息。
- 历史消息按稳定游标分页，时间顺序不因分页刷新而错乱。
