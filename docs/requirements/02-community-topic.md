# 需求二：社区与主题浏览

## 1. 目标

以社区为边界分发主题，确保用户只看到自己所属社区的内容；主题发布者可以设置年龄和性别等参与约束。

## 2. 主题字段与规则

- 必填：标题、详情、所属社区（由当前用户社区自动带入）。
- 可选：最小年龄、最大年龄、允许性别、过期时间。
- 标题和详情需做长度、敏感内容、非法链接校验。
- 主题发布后社区快照固定，不因发布者之后切换社区而改变归属。
- 主题状态：`开放`、`已关闭`、`已取消`、`已过期`。只有开放且未过期的主题可分发给新用户或接受新的参与。

## 3. 发布主题主流程

1. 用户进入发布页填写标题、详情和约束。
2. 客户端展示约束预览，提交后服务端重新校验。
3. 服务端读取用户当前社区，创建主题并记录发布审计日志。
4. 系统异步筛选同社区且满足约束的其他用户，生成主题推送收件记录并发送通知；分发重试不得重复生成收件记录。
5. 发布者看到主题详情和参与人数；接收用户在主题流或推送收件列表中看到主题并自主选择接受。发布时不创建聊天室，首次有其他用户接受时才自动创建。

## 4. 浏览与匹配流程

1. 用户请求主题流。
2. 系统只查询用户当前社区的开放主题。
3. 对设置了约束的主题，按用户资料匹配：年龄缺失时不能满足年龄限制；性别缺失时不能满足指定性别限制。
4. 返回分页结果，并标识用户推送处理状态、是否已参与及是否已读。
5. 用户打开主题详情时再次执行权限校验，防止通过旧链接访问其他社区内容。

## 5. 关闭与过期

- 发布者可主动关闭自己的主题；关闭后保留历史参与和聊天记录，但不允许新增参与。
- 到达 `expires_at` 后系统任务将主题置为过期。
- 已接受的参与者不因主题关闭而自动移出聊天室；允许原成员继续发送消息和查看历史，但禁止新成员加入。

## 6. 异常流程与验收

- 不同社区用户通过列表、详情或猜测 ID 访问主题，均不得泄露主题存在性。
- 年龄范围不完整、最小年龄大于最大年龄、未知性别枚举等请求必须拒绝。
- 同一主题流刷新不能产生重复主题或重复收件记录。
- 发布、关闭、过期后状态和可操作按钮一致，服务端状态为最终依据。
