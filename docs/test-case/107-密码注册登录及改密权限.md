# user-case 107 密码注册登录及改密权限

认证。测试目的：邮箱/手机号注册设置密码、密码登录、本人修改密码，并验证不能借其他账号的密码修改当前账号。

## 执行约定

- 测试环境须提供至少一个社区，注册验证码使用当前开发环境发送接口固定返回的 `000000`；若测试环境使用真实验证码服务，需从测试环境安全渠道取验证码，不能把此固定值当作通用验证码。
- `run=generateUUID()`；邮箱使用 `tc-${run}-角色@example.com`；昵称用不同的固定值。手机号使用 `139000000099`，执行前确认未被占用；若已占用先换一个专用测试号码。
- 密码仅用于本例，使用 `Pass-A-Original-2026`、`Pass-B-Original-2026`、`Pass-A-New-2026`、`Pass-A-Wrong-2026`。执行记录、报告和日志不得输出密码或密码哈希。
- 每个成功注册响应立即登记用户 ID、accessToken、refreshToken、identityValue；断言失败也按 finally 清理所有已登记账号。

## 接口调用步骤

1. `GET /api/v1/communities`，保存 `C1=data[0].id`；无社区则阻塞。
2. 生成 A、B 两个唯一邮箱。分别调用 `POST /api/v1/auth/send-code`，提交 `identityType=email`、对应邮箱、`purpose=register`；再调用 `POST /api/v1/auth/register`，提交 `identityType=email`、对应邮箱、`code=000000`、各自密码、昵称和 `communityId=C1`。预期均 HTTP 200、code=0；保存各自 user ID 和 accessToken。
3. 使用 A 的邮箱和 `Pass-A-Original-2026` 调用 `POST /api/v1/auth/login`，只传 `password` 不传 `code`。预期 HTTP 200、code=0，返回 `user.id=A.id`。
4. 使用 `139000000099` 作为 B 的 phone identity 注册：先 `POST /api/v1/auth/send-code`，`identityType=phone`、`purpose=register`；再 `POST /api/v1/auth/register`，传 `code=000000`、`Pass-B-Original-2026`、昵称和 `C1`。预期 HTTP 200、code=0。保存 B 的 ID 和 accessToken。使用该手机号和 `Pass-B-Original-2026` 调用密码登录，预期 `user.id=B.id`。
5. 调用 `POST /api/v1/auth/send-code` 为 A 发送 `purpose=login` 的验证码。随后用 A 的邮箱调用登录，同时提交 `code=000000` 和 `password=Pass-A-Original-2026`。预期 HTTP 400、code=40001：验证码和密码不能同时填写。
6. 使用 `Authorization: Bearer ${A.accessToken}` 调用 `PUT /api/v1/auth/password`，请求体为 `{"currentPassword":"Pass-A-Wrong-2026","newPassword":"Pass-A-New-2026"}`。预期 HTTP 401、code=40101；错误当前密码不能修改凭据。
7. A 使用正确当前密码 `Pass-A-Original-2026` 调用改密接口，目标密码为 `Pass-A-New-2026`。预期 HTTP 200、code=0、data={}。
8. A 使用新密码登录成功且 `user.id=A.id`；再使用旧密码登录，预期 HTTP 401、code=40101。
9. 使用 B 的 accessToken 调用改密接口，请求体传 A 的原密码和一个新密码。预期 HTTP 401、code=40101。随后确认 A 使用 `Pass-A-New-2026` 仍能登录，证明 B 的请求没有改变 A 的凭据。
10. 不带 Authorization 调用 `PUT /api/v1/auth/password`，预期 HTTP 401、code=40101。

所有失败响应不得包含堆栈、SQL、密码或密码哈希。

## 期待结果

注册密码可以登录；邮箱与手机号身份均可使用密码登录。改密只作用于 bearer token 对应的账号，必须验证该账号当前密码；失败请求不改变任何账号的密码。

## 清理（finally）

对本例每个成功注册且仍登记的账号，分别使用该注册响应的 accessToken 调用 `DELETE /api/v1/me`，预期 HTTP 200、code=0、data={}。不通过 SQL 删除用户。
