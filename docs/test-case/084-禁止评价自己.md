# user-case 084 禁止评价自己

评价校验。测试目的：非法评价不落库且返回参数错误

## 执行约定

- 测试环境不预置用户或业务数据，基础字典已由环境初始化；不通过 SQL 插入社区或评价分类。
- 本文件独立执行。`${变量}` 表示运行时替换，并非字面量；`generateUUID()` 由执行器产生 UUID。服务端分配的用户、主题、聊天室、消息、评价 ID 一律提取自本文件此前 HTTP 响应；仅构造不存在资源的负例 ID、客户端消息 ID、设备 ID 和请求 ID 时使用 `generateUUID()`。
- JSON 使用当前 OpenAPI 定义的 camelCase（如 `communityId`、`accessToken`、`requestId`），评价汇总的字段保留 `good_count` 等 snake_case。主题约束直接放 `minAge/maxAge/genders`，不套 `constraints`。
- 所有有请求体的调用携带 `Content-Type: application/json`。未列出的 query 参数省略；未列出的 body 字段不发送。成功还需检查统一响应 `message`、`data`、非空 `requestId`；错误需检查业务码且不能出现堆栈、SQL 或凭证。
- `run=generateUUID()`；`code` 为运行时生成的六位随机数字字符串。按测试环境已关闭邮箱验证码校验的约定使用此随机值；若登录仍验证验证码，记录环境/实现缺陷，不改用硬编码万能验证码。邮箱使用 `tc-${run}-角色@example.com`，昵称使用 `测` 加该角色单独 `generateUUID()` 去连字符后的前 12 位。
- 断言失败也进入本文件清理步骤；每个成功注册响应立即登记 `user.id/accessToken/refreshToken/identityValue`，包括负例意外成功的响应。


## 接口调用步骤

1. `GET /api/v1/communities`；不带 Authorization；无请求体。预期：HTTP 200、code=0。保存 `C1=data[0].id`；断言非空且每项 id 为 UUID、name 非空。若无可用社区，本例阻塞。
2. 生成 `A.email=tc-${run}-a@example.com`、`A.nickname`（按前述规则），然后 `POST /api/v1/auth/register`；不带 Authorization；JSON：`{"identityType":"email","identityValue":"${A.email}","code":"${code}","nickname":"${A.nickname}","communityId":"${C1}"}`。预期：HTTP 200、code=0。保存 `A.id=data.user.id`、`A.access_token=data.accessToken`、`A.refresh_token=data.refreshToken`。
3. 生成 `B.email=tc-${run}-b@example.com`、`B.nickname`（按前述规则），然后 `POST /api/v1/auth/register`；不带 Authorization；JSON：`{"identityType":"email","identityValue":"${B.email}","code":"${code}","nickname":"${B.nickname}","communityId":"${C1}"}`。预期：HTTP 200、code=0。保存 `B.id=data.user.id`、`B.access_token=data.accessToken`、`B.refresh_token=data.refreshToken`。
4. `POST /api/v1/topics`；Authorization: `Bearer ${A.access_token}`；JSON：`{"title":"测试-${run}","detail":"独立接口验收","genders":[]}`。预期：HTTP 200、code=0。保存 `T=data.id`，断言 publisherId=${A.id}、communityId=${C1}、status=open。
5. `GET /api/v1/topics/receipts?status=pending&limit=100`；Authorization: `Bearer ${B.access_token}`；无请求体。预期：HTTP 200、code=0。断言 items 中恰有一项 topicId=${T}。若异步分发，每秒真实等待后重试此查询，最多 30 秒，超时失败。 然后 `POST /api/v1/topics/${T}/accept`；Authorization: `Bearer ${B.access_token}`；无请求体。预期：HTTP 200、code=0。保存 `R=data.roomId`，断言 topicId=${T}、status=accepted，roomId 非空。
6. `POST /api/v1/topics/${T}/ratings`；Authorization: `Bearer ${A.access_token}`；JSON：`{"toUserId":"${A.id}","score":"good","categoryCodes":[],"comment":"边界评价"}`。预期：HTTP 400、code=40001。
7. `GET /api/v1/users/${A.id}/ratings?limit=100`；不带 Authorization；无请求体。预期：HTTP 200、code=0。没有本例非法评价。

## 期待结果

非法评价不落库且返回参数错误。所有读取结果均按本例 ID 或身份筛选，不依赖数据库全局条数。

## 清理（finally）

1. 先用仍有效的本例成员令牌调用 `GET /api/v1/rooms`（无请求体），按本例主题 ID 筛选，补录所有 roomId；无主题或未建房则跳过。已在业务步骤成功注销并从登记表移除的账号不再重复注销；尚未成功注册的角色跳过。
2. `DELETE /api/v1/me`；Authorization: `Bearer ${B.access_token}`；无请求体。预期：HTTP 200、code=0、data={}，该用户从登记表移除。 随后 `GET /api/v1/me`；Authorization: `Bearer ${B.access_token}`；无请求体。预期：HTTP 401、code=40101。
3. `DELETE /api/v1/me`；Authorization: `Bearer ${A.access_token}`；无请求体。预期：HTTP 200、code=0、data={}，该用户从登记表移除。 随后 `GET /api/v1/me`；Authorization: `Bearer ${A.access_token}`；无请求体。预期：HTTP 401、code=40101。
4. 遍历成功注册登记表中的全部剩余账号（包括步骤中额外注册的 A、B、A2 以及负例意外成功账号），逐个使用其成功响应的 accessToken 调用 `DELETE /api/v1/me`（无请求体），确认 HTTP 200、code=0。不要仅删除数据库用户来替代注销接口。
5. 账号注销按契约保留聊天室和历史消息。完成保留行为断言并注销本例全部用户后，对本例 HTTP 响应取得的聊天室 ID 集合逐个参数化执行 `DELETE FROM chat_room WHERE id = :room_id;`（`:room_id` 只能取本文件保存的 R/R2 等响应值；外键级联删除消息和已读数据）。若接受请求异常后未取得 roomId，先用本例仍有效成员令牌 `GET /api/v1/rooms`（无请求体）按本例主题 ID 筛选并补录 ID，再注销。无聊天室则跳过；不得全表清理。
