执行前阅读公共准备。每个用例独立从空业务库开始，按其依赖配方创建数据；不得依赖其他用例执行后的残留。表格的各行也是独立子场景，应分别重新准备数据。用例内连续步骤共享数据。

文件以 `00`～`08` 数字前缀编号；用例以 `01-01` 等编号，数据表独立场景以 `01-02-01` 等编号。依赖数据说明对应接口和提取字段，步骤中的变量从本用例响应取得。公共准备包含完全空库验证、字典初始化要求和端到端链路。

请求和响应字段以 `src/main/resources/rest-api/*.yaml` 为准，业务规则参照 `docs/requirements/`；`docs/rest-api.md` 中旧版 snake_case 字段不直接作为请求字段。当前 28 个操作成功响应均定义为 HTTP 200，统一检查 `code=0`；业务拒绝检查 HTTP 4xx、业务码、错误描述和无副作用，受控内部故障检查 5xx 和补偿结果；所有响应检查非空 `requestId`。失败码映射尚未写入 YAML，暂按公共准备中的业务语义验收，并记录契约差异。

需求差异处理：

- 需求七已确认昵称可重复、关闭后原成员可继续聊天、系统评级对所有用户可见，相关用例采用这些结论。
- 需求七要求主题推送给所有匹配用户，但尚无明确的自动生成邀请/收件记录契约；自动推送单列为待契约确认用例，其他参与链路通过现有邀请接口准备。
- 年龄仅设置一个上下限在需求二和 REST 文档中表述冲突，单列待确认；两个边界都省略或同时提供的场景可直接执行。
- 评价匿名、申诉、移除成员、封禁、社区初始化、任务触发及运营证据查询没有对应公开 API，不虚构接口；涉及这些能力的用例注明环境依赖，未提供时记录为阻塞。
- 限流、验证码错误次数、评级阈值等取测试环境真实配置；没有明确阈值时不能自行判定通过。长度有 OpenAPI 明确约束的按契约执行，其余取已确认配置。

执行记录建议：用例 ID、环境/版本、执行时间、实际状态码及脱敏响应、实际结果、通过/失败/阻塞、缺陷编号。保留 requestId，勿保存验证码或令牌原文。
