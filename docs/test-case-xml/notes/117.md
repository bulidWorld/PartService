# TC-117 转换说明

- 来源：`docs/test-case/117-rating-pagination.md`。目标为 USER_B 公开评价列表的游标分页：首页 limit=2 须 2 条、hasMore=true、nextCursor 非空；第二页带 cursor 须 1 条、hasMore=false、nextCursor=null；两页并集恰为三条评价且无重叠，验证无重复无遗漏。
- 准备链：GET /communities 取第一项 id 作 COMMUNITY_A（不足则 Blocked，公开 HTTP 无社区创建接口）；GET /rating-categories 检查 data 数组含 reliable（缺少则 Blocked，不创建或修改分类）；注册 A（email 782213745@qq.com）与 B（phone 13900000002）；A 依次创建 3 个主题并邀请 B，B 依次接受（roomId 须为非空 UUID），A 对每个主题给 B 一条 good/reliable 评价并提取 R1/R2/R3。
- 分页断言通过集合运算表达：每页条目的 id、topicId、fromUserId、toUserId、score、categories 逐项核对；首页提取 data.nextCursor→CURSOR 与 data.items→FIRST_ITEMS（array）；第二页要求与 FIRST_ITEMS 的 id 集合不相交且并集等于 {R1,R2,R3}。GET /users/{userId}/ratings 在 OpenAPI 中未声明 security，与源用例不带 Authorization 一致，XML 用 auth none。
- 准备步骤（社区、分类、注册、主题、邀请、接受、评价创建）失败一律 raise Blocked 并停止后续业务；目标分页步骤（第 17/18 步）失败直接 assert 记为失败。所有变量仅来自本文件前序响应；注册断言失败仍提取 user.id/accessToken/refreshToken，finally 清理本次实际创建的账号，不删除来源不明的已有身份。
- finally 顺序清理 B/A：先 GET /me 探测（200/code=0 且 id 匹配；401/code=40101 时先 POST /auth/refresh 并用 updateParam 更新 TOKEN/REFRESH）；DELETE /me 断言 HTTP 200/code=0/data={} 与非空 requestId，提取业务码及 requestId 供执行记录；随后旧、新访问令牌 GET /me 及旧、新刷新令牌 POST /auth/refresh 均须 HTTP 401/code=40101。单步失败不阻断其他清理；401 不代表账号已删除，凭证不足导致无法确认时按源用例记录“清理失败/未确认”。
- 阻塞/无法表达项：
  - XML 格式无法表达：源用例“清理失败/未确认时停止复用当前环境并停止后续用例”是跨任务调度约束，单 XML 无法表达，须由调度器串行使用共享身份并据清理结果停止后续任务（同 092 注释约定）；“执行记录”中实际 HTTP/业务码、requestId、结论与脱敏响应由执行者/调度方记录，XML 仅提取 DELETE_CODE/DELETE_REQUEST_ID 与 CLEANUP_PROBE_CODE 供记录。
  - 业务接口缺口：本用例判定依据全部可通过公开 HTTP 观察（列表接口响应与清理核查），无内部存储依赖；社区与评价分类缺少创建接口，数量不足时按源用例阻塞处理。
- 可表达性结论：XSD/导入器可表达全部主流程与清理。OpenAPI 未声明 GET /me、POST /auth/refresh 的 401 响应及 DELETE /me 语义细节，清理断言按源用例明确要求的真实 HTTP/业务码验证（401/code=40101）。
