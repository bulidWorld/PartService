# 用例 052 生成说明

- SQL 占位符：md 的 :user_id 改写为 %s 并按顺序绑定 <parameter>a_id</parameter>；datasource 使用 jdbc:postgresql://127.0.0.1:5432/part_service_db、username=part_service、password=Changeme_123（与 application.yml 默认值一致）。表名 "user" 与列 community_changed_at 已对照 src/main/resources/db/01-user-auth.xml 核实。
- 昵称：md 要求"测+UUID 去连字符前 12 位"，compute 无 substring/去连字符截取能力 → 改为固定昵称（A=测052甲、B=测052乙、X=测052戊）。
- 验证码 code：compute 无随机数字函数 → 固定 "123456"（测试环境已关闭验证码校验）。
- 双社区前提：GET /communities 断言中 data 不足 2 项时 raise Blocked；c2=data[1].id 提取失败时依赖 c2 的注册与切社区步骤以 ifParameter="c2" onFalse="blocked" 兜底，不写死或 SQL 创建社区。
- 断言沙箱禁止 re，社区条目 id 的 UUID 格式只断言非空（与 002 样例同风格）。
- 清理：本用例没有任何成功的接受请求，不会产生聊天室，md 清理第 1/6 步"无聊天室则跳过"，故省略 GET /rooms 补录与 chat_room 的 SQL 清理。
