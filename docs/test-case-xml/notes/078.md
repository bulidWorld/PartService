# TC-078 转换说明

- 来源：`docs/test-case/078-invitation-concurrent-accept.md`；生成同 stem XML，未执行 HTTP。
- 独立准备：公开社区查询、A 邮箱及 B 手机注册、A 创建主题并邀请 B；注册响应立即分别提取用户 ID、访问/刷新令牌及原始令牌副本。社区或注册前提不足为 Blocked，仍执行 finally。
- `parallel maxConcurrency="2"` 发送完全相同的两个接受请求，各自保存业务码和响应 data，避免兄弟参数写冲突。成功必须 HTTP 200/code=0、accepted 且身份/主题/邀请吻合；仅允许 HTTP 409/code=40901 的冲突分支，并对每个冲突执行一次接受重试，重试必须成功，从而验证“可重试”。该业务码依据 `ApiException.conflict`；OpenAPI 未列出该错误响应，属于 HTTP 契约描述缺口。
- B 的邀请列表核查 I 最终 accepted，所有成功接受及冲突重试的 data 必须一致（冲突重试覆盖对应已声明的响应 data 参数）；从最终查询提取 ROOM。房间详情要求成员恰为 A、B 各一个，A/B 房间列表要求 topicId=T 只出现一项、房间及成员详情一致。要求分页已穷尽，避免只核查首批却声称全量唯一。
- HTTP 可观察的参与关系通过 B 的房间列表唯一性及房间成员唯一性核查；没有独立参与关系查询接口，不能声称已验证底层参与表或内部存储唯一性。无内部存储/广播/日志断言，符合源用例的 HTTP 可观察边界。
- finally 依次处理 B、A；GET /me 探测访问令牌，40101 时刷新并更新清理凭证，随后 DELETE /me 必须 200/code=0/data={} 且 requestId 非空，再逐一核查注册原始及当前访问/刷新令牌均 401/code=40101。失败不阻断另一用户清理。
- 任务级 finally 能记录逐用户清理失败，但无法表达跨任务停止后续调度、环境空态认证或共享身份全局互斥；执行者必须串行复用身份，任何清理失败/未确认均停止后续用例，不能凭 401 推断账号已删除。
- XSD 采用现存 `docs/test-case-xml/task.xsd`，无 schema 修改。并发屏障保证并发发起机会，不能保证服务端事务精确同时进入；单次运行不能证明所有竞争交错。
- 校验：指定 AutoTestService 虚拟环境运行 `validate.py`（1 XML，0 errors）及 `validate_importer.py --importer-root /opt/apps/Deployment/AutoTestService`（1 XML，0 errors），均通过；仅离线检查，未连接数据库或发起 HTTP。
