# TC-019 已注册邮箱登录

- 输出：`019-login-email.xml`。离线 XSD、参数引用、断言 AST 与沙箱内建校验通过，未发送 HTTP。
- 完整保留社区查询、邮箱注册、发送登录验证码、固定 `246810` 登录及新令牌 `/me` 查询。注册立即提取 ID、访问/刷新令牌；登录失败仍提取可用返回字段，finally 保留注册凭证清理。登录用户必须等于注册用户，新访问令牌必须非空并不同于注册令牌。
- 清理：只注销本次注册 USER_A，先查询其注册访问凭证状态，40101 时以注册刷新令牌恢复，注销后逐一核查注册、登录及清理刷新签发的访问/刷新令牌失效；注销断言包含 HTTP 200、code=0、data={}、requestId。清理请求均有明确状态和业务码；失败继续尝试后续核查。响应丢失导致未能获得清理凭证不能视为注销成功。

## XSD 表达能力缺口

- 清理前要求将同一用户最新的登录令牌复制为当前清理凭证，同时在登录失败时保留注册凭证。当前 updateParam 在缺失响应字段时覆盖为 null，compute 仅能声明新参数，受限表达式不支持条件表达式，条件 equals 仅支持 JSON 字面量，缺少“动态比较用户 ID 后有条件从已有参数更新变量”的表达方式。XML 因此保留注册凭证用于该账号注销及过期刷新，并另外验证登录凭证注销后失效；不能宣称已覆盖“总是以最新登录令牌注销”的细节。异常登录返回其他用户 ID 时不能确认该账号系本次创建，禁止贸然删除。
- 同邮箱串行复用、清理失败停止后续独立任务、日志脱敏和逐用户清理结论需要跨任务执行器实施，单 task 无法约束后续任务。已标记 token 参数 sensitive，HTTP 记录中的验证码仍需执行器脱敏。

## HTTP 接口及实现差异

- 当前 `UsersControllerImpl.listCommunities()` 固定返回空数组，现有公开 HTTP 无社区创建接口；实际执行将前提阻塞，不记作登录场景通过。
- `AuthControllerImpl.sendCode()` 保存 `000000`，`login()` 无条件调用 `verifyCode()`；只有注册读取 `register_verify_code`。在社区前提补齐后，固定 `246810` 登录预期暴露实现与免校验约定差异，XML 不替换真实验证码，不将拒绝判为通过。
- 未公开用户总量查询，登录返回原用户并通过 `/me` 核查能够验证身份一致性，无法独立证明数据库用户总数不增加。
- 环境是否为空、验证码开关状态未公开 HTTP 查询；沿用源用例外部前提，不删除来源不明已有账号。
