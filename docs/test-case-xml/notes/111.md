# TC-111 转换说明

- 来源：`docs/test-case/111-rating-invalid-category.md`。独立准备社区、注册 A/B、创建主题、邀请并接受后，A 对 B 提交含不存在分类编码 `not_a_category` 的评价，预期 HTTP 400/code=40001、响应不返回评价 ID，随后 B 的公开评价列表为空。
- 逐步骤转换：步骤 1 `GET /communities` 提取 COMMUNITY_A，无社区或 ID 不可取得时 Blocked；步骤 2/3 注册 A（邮箱 782213745@qq.com）/B（手机 13900000002），失败 Blocked 并停止业务，断言失败仍提取 user.id/accessToken/refreshToken 及原始副本供 finally 清理与失效核查；步骤 4/5/6 创建主题、邀请、接受，提取 T/I/ROOM，ROOM 做 36 位 UUID 格式校验；步骤 7（目标）`POST /topics/{topicId}/ratings` 以 ROOM 为前置条件，body 绑定 toUserId=USER_B、score=good、categoryCodes=["not_a_category"]、comment，断言真实 HTTP 400、业务码 40001（ApiException.bad）、非空 requestId、data 为 null 或空对象且响应键仅限通用信封（不返回评价 ID），message 中不含 USER_B/T；步骤 8（目标）`GET /users/{userId}/ratings?limit=20` 公开列表断言 items==[]、hasMore==false、nextCursor==null。
- 分类编码：OpenAPI RatingRequest.categoryCodes 的 items 为无枚举 string，"not_a_category" 可通过 body 绑定构造并通过接口 Schema 校验，业务层 RatingRepository.CATEGORIES 校验拒绝并返回 400/40001，因此未使用 rawBody；业务码以源用例 md 及 ApiException.bad 为准。
- 失败语义：社区/注册/主题/邀请/接受为业务准备，失败 raise Blocked（终态 blocked，仍执行 finally）；步骤 7/8 为目标断言，失败直接 assert。所有变量来自本文件前序响应。
- finally 顺序清理 B/A：先 GET /me 探测（200/code=0 且 id 匹配；401/code=40101 时 POST /auth/refresh 并用 updateParam 覆盖当前访问/刷新凭证）；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码及 requestId 供清理记录；随后分别用原始与最新访问令牌 GET /me、原始与最新刷新令牌 POST /auth/refresh 核查 HTTP 401/code=40101。每步带 ifParameter 条件，单步失败继续其他清理；401 不代表账号已删除，未注册的用户跳过。
- 阻塞/无法表达项：
  - XML 格式无法表达：清理失败须由调度器停止后续共享身份任务，单 XML 无法表达，调度方须串行执行并核查清理结论；执行记录（脱敏响应、实际 HTTP/业务码、requestId、结论）由执行者维护，不在 XML 内。
  - 业务接口缺口：无。评价未创建由步骤 8 公开列表为空覆盖；聊天室无公开删除接口，源用例清理节未要求清理聊天室，两用户注销后其主题、参与、邀请和评价由服务端按 DELETE /me 契约删除，不做额外断言。
- 可表达性结论：源用例流程与期待结果全部可由 XSD/导入器表达；「响应不返回评价 ID」以错误响应 data 为 null/空对象且键仅限信封的形式断言。
