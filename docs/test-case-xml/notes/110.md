# TC-110 转换说明

- 来源：`docs/test-case/110-rating-invalid-score.md`。独立查询社区与评价分类，注册 A（邮箱 782213745@qq.com）/B（手机号 13900000002），A 创建主题并邀请 B、B 接受形成共同参与，随后 A 以 `score=excellent` 提交评价，预期 HTTP 400、code=40001；公开列表 `GET /users/{USER_B}/ratings` 为空且响应不返回评价 ID。
- 服务实现中评分枚举校验（good/neutral/bad，`评分无效`）位于业务校验最后一步，之前依次校验自我评价、分类有效性、双方共同参与、重复评价；因此必须完整保留主题→邀请→接受准备链路，否则会命中 409/其他分支而无法验证非法评分。
- OpenAPI `RatingRequest.score` 仅为 `type: string` 且无枚举，结构化 body 绑定可构造 `"excellent"`，不会被导入层 Schema 校验拒绝，故按 XSD 使用普通 body 绑定，其余位置（路径/查询/必填）仍严格校验；业务码 40001 来自 `ApiException.bad`，与源用例一致。
- 准备步骤（社区、分类、注册、主题、邀请、接受）失败均 raise Blocked；步骤 8（目标：HTTP 400/code=40001/requestId 非空/data 为 null/响应不含 id）与步骤 9（公开列表 items 为空、hasMore=false、nextCursor=null）直接 assert。所有变量来自本文件前序响应。
- finally 顺序清理 B→A：先 GET /me 探测，401/40101 时先刷新并用 updateParam 覆盖当前访问/刷新凭证；DELETE /me 断言 HTTP 200/code=0/data={} 与非空 requestId，提取业务码及 requestId 供记录；随后旧/新访问令牌 GET /me、旧/新刷新令牌 POST /auth/refresh 均断言 HTTP 401/code=40101。单步失败不阻断后续清理；401 不代表账号已删除。
