# TC-129 转换说明

- 来源：`docs/test-case/129-risk-public-visibility.md`。源用例主题为「系统评级对其他用户可见」，头部执行条件即为「阻塞：缺少 HTTP 接口」；仅核查公开契约可访问的接口，不能验证他人可见性。
- 逐步骤转换要点：
  - 源用例步骤 1 为现状说明：本人 GET /me/rating-summary 有 risk_tags；他人评价列表只返回评价明细；当前没有读取他人系统评级的 HTTP 接口。核对 ratings.yaml：GET /me/rating-summary 声明 bearerAuth，RatingSummary 含 risk_tags；GET /users/{userId}/ratings 无 security 声明（公开查询），返回 Rating 明细（id/topicId/fromUserId/toUserId/score/categories/comment/createdAt），不含风险标签或系统评级字段；全部 OpenAPI 无 risk 相关接口，因此未虚构任何查询接口。
  - 源用例步骤 2（`GET /rating-categories`）转换为 taskStep 10：公开接口探针，auth mode=none，断言 HTTP 200/code=0、requestId 非空、data 为数组；探针失败按「准备请求失败」raise Blocked。
  - 源用例步骤 3（结论为阻塞）转换为 taskStep 20：复用只读、公开、幂等的 `GET /rating-categories` 作为 Blocked 载体（assertionCode 只允许出现在 rest 步骤内），重复核查响应后 raise Blocked，终态 blocked。按源用例期待结果，查询接口调用成功不能代替目标场景通过，不在任何断言中声称通过。
  - 本用例不注册用户、不创建业务数据，故省略 finally。
- 阻塞/无法表达项：
  - 业务接口缺口：源用例目标本身需要读取他人系统评级的 HTTP 接口，公开契约没有该能力（/me/rating-summary 仅本人可见且需鉴权；/users/{userId}/ratings 只返回评价明细）；转换以最后一步 raise Blocked 落盘原因，未虚构接口，也未把探针成功记为目标场景通过。「不暴露内部证据」的核查同样缺少公开 HTTP 手段。
  - XML 格式无法表达：源用例头部元数据（优先级 P1、执行条件「阻塞：缺少 HTTP 接口」、执行记录表格）在 task.xsd 中无对应字段，由 task name 与本文档承载。
- 清理说明：本用例未创建任何用户或业务数据，无测试后清理需求，省略 finally；共享身份串行执行不受本用例影响。
