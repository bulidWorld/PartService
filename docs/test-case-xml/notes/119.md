# TC-119 转换说明

- 来源：`docs/test-case/119-rating-concurrent.md`。独立查询社区与评价分类，注册 A（邮箱 782213745@qq.com）/B（手机 13900000002），创建主题后，在同一 parallel 屏障内用两个完全相同的 `POST /topics/{topicId}/ratings`（maxConcurrency=2）同时提交 A→B 的 good/reliable 评价，不等待第一个响应再提交第二个。
- 源用例步骤 6-7（A 邀请 B + B 接受邀请）已映射为当前公开 API 的 `POST /topics/{topicId}/accept`：当前服务契约已移除 invitations 模块（invitations.yaml 已删除），由被邀请侧 B 直接接受主题参与，响应 TopicReceipt 断言 topicId=T、status=accepted、roomId 为非空 UUID、readAt=null、createdAt 非空，并提取 ROOM。转换以当前 OpenAPI 为准。
- 步骤 1-2 GET /communities 提取 data[0].id 到 COMMUNITY_A；GET /rating-categories 核对 data 含 reliable，缺少即 Blocked（不创建或修改分类）。步骤 3-4 注册 A/B 并保存 user.id、访问/刷新令牌（含 ORIGINAL 副本供失效核查）。步骤 5 建主题保存 T，步骤 6 B 接受主题保存 ROOM。
- 步骤 7（parallel，order=70，ifParameter=ROOM）：两个叶子各提交同一评价。每个叶子按可接受结果集断言——成功为 HTTP 200/code=0 且 data 满足 topicId=T、fromUserId=USER_A、toUserId=USER_B、score=good、categories 含 reliable、comment 不变；冲突为 HTTP 409/code=40901、data 为空、非空 requestId/message 且 message 不泄露双方身份与评论内容（业务冲突码来自 ApiException.conflict，对应「该主题已评价」）。源用例允许一成功一冲突或两笔返回同一结果；两叶子提取互不重名的 RATING_CODE_x/RATING_ID_x。
- 步骤 8 GET /users/{userId}/ratings?limit=20（公开接口无鉴权）断言 hasMore=false、nextCursor=null、items 恰一条，item 为 T、A→B、score=good、comment 不变，且任一成功响应提取的 RATING_ID_x 与 item.id 一致；并发重复落库出现两条即目标断言失败，实现「最终只有一条 T、A→B 评价」。列表响应 categories 由持久化映射恒为空（RatingEntity 无分类列），故列表断言只核对源用例要求的 score/comment 等字段，不断言 categories。
- 步骤 9 GET /me/rating-summary（TOKEN_B）：源用例要求 total_count=1、good_count=1。业务接口缺口——当前实现返回固定零值（RatingsControllerImpl.getMyRatingSummary），无法通过公开 HTTP 观察真实计数，按「仅公开 HTTP 可观察」原则未虚构该断言；核对信封（200/code=0/非空 requestId）及字段类型后 raise Blocked 说明原因，并提取 TOTAL_COUNT/GOOD_COUNT 供执行记录。OpenAPI 未声明评价 409 及清理步骤的 401 响应，断言按源用例允许的明确状态验证真实 HTTP/业务码。
- 准备失败均 Blocked；注册断言失败仍提取 user.id/accessToken/refreshToken，finally 清理本次实际创建的账号，不删除来源不明的已有身份。所有变量来自本文件前序响应。
- finally 顺序清理 B/A：先 GET /me 探测，40101 时刷新并更新当前访问/刷新凭证；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码及 requestId 用于记录；逐一核查原始及最新访问/刷新凭证 HTTP 401/code=40101。单步失败仍继续其他清理；401 不代表账号已删除。
- XML 格式无法表达：清理失败或未确认时由调度器停止后续任务无法由单 XML 表达，调度方须串行使用共享身份，清理失败立即停止环境复用；源用例执行记录表（脱敏手工记录）不在 XML 内。业务接口缺口：/me/rating-summary 实现返回固定零值，total_count=1/good_count=1 无法验证，以最后一步 Blocked 记录为阻塞；并发只计数一次由公开列表恰一条的目标断言在 HTTP 层面验证。另：源用例的邀请/接受流程随服务契约重构已不存在，转换改用主题接受接口，属接口演进适配而非阻塞。
- 仅生成；未执行 HTTP、部署或数据库操作。XSD/OpenAPI 离线校验结果见交付简报。
