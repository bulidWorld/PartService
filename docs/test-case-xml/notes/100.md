# TC-100 转换说明

- 来源：`docs/test-case/100-chat-untrusted-image.md`。独立查询社区、注册 A/B（邮箱 782213745@qq.com、手机 13900000002）、创建主题、邀请并接受入群，A 发送非可信域图片消息，期待 HTTP 400/code=40001，随后 B 查询消息历史为空；仅验证拒绝响应和历史结果。
- 源用例标记待附件规则确认（与 TC-030 头像拒绝用例同条件）。固定参数 `ATTACHMENT_RULES_CONFIRMED=false` 在注册前经 `ifOperator="truthy" onFalse="blocked"` 停止主流程，规则未确认时不创建任何用户；完整流程保留供规则确认后评审启用，届时须评审该 URL 确为拒绝样本再更新门禁。不将社区查询成功记作目标通过。
- 步骤 7 负向请求体用 rawBody 原样发送（含 contentMeta.url/mimeType/size 的 JSON 字面量）：绑定引擎按「整串恰为 {参数名} 即引用」规则解释字面值，`{"url": ...}` 形状的 body/kv 字面量无法表达；pathParams 的 roomId 仍严格绑定。rawBody 仅支持声明 application/json 的接口，`POST /rooms/{roomId}/messages` 满足（同 086、030 先例）。
- 拒绝响应断言 HTTP 400/code=40001、非空 requestId、data 为 null 或 {}、信封键仅 code/message/data/requestId；随后 `GET /rooms/{roomId}/messages?limit=20` 断言 items 为空、hasMore=false、nextCursor=null。目标断言失败记为失败（行为与预期不符），准备失败 Blocked，不阻塞 finally。
- finally 顺序清理 B/A：先 GET /me 探测（200/code=0 且 id 匹配，或 401/code=40101），40101 时 POST /auth/refresh 并用 updateParam 更新当前访问/刷新令牌；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码及 requestId 用于记录；原始及最新访问令牌 GET /me、原始及最新刷新令牌 POST /auth/refresh 均断言 401/code=40101。每步带 ifParameter，单步失败不阻断后续清理，未创建账号自动跳过。
- 阻塞/无法表达项：
  - XML 格式无法表达：附件 URL、类型和大小规则无任何 HTTP 查询接口，规则确认状态只能用固定参数门禁表达，确认后需人工评审并更新门禁；跨任务共享身份串行复用、清理失败/未确认停止后续任务须由调度器保证（同 092/030）；执行记录表及脱敏记录由执行者填写。
  - 业务接口缺口：rooms.yaml 仅声明 200 响应，400/code=40001（拒绝）与 401/code=40101（凭证失效）按源用例期待校验真实 HTTP/业务码（同 086/092 先例）。
- XSD/导入器可表达本文件流程；validate.py 离线校验 0 错误。仅生成；未执行 HTTP、部署或数据库操作。
