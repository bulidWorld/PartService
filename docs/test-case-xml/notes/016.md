# TC-016 转换记录

- 来源：`docs/test-case/016-register-duplicate-identity.md`；产物：`016-register-duplicate-identity.xml`。
- 完整保留社区准备、首次注册、重复注册（源用例验证码 `135790`）、409/40901 与无新账号/凭证断言、原凭证查询原 ID/昵称。验证码校验关闭时源用例的不同验证码不影响重复身份分支。
- 两次注册均立即提取用户 ID、访问/刷新令牌与原令牌副本；断言失败仍供 finally 清理。首次注册 409 为已有身份前提不足，禁止删除已有账号。
- finally 尝试 A 清理并检查所有令牌；意外注册 B 随后独立清理。B 与 A 同 ID 时，A 注销后 B 探测/刷新应为 401，刷新提取的 null 使 B 注销跳过，原 B 凭证仍核查；不同 B 则逐个注销。访问凭证 401 时尝试本人刷新。清理记录由逐步骤响应提供 HTTP/业务码与 requestId，令牌参数均脱敏。

## XSD / 执行能力缺口

- 跨任务邮箱串行复用、清理失败停止整个任务组不能仅由单任务 XSD 强制；须执行器串行调度并在清理失败或未确认时停止后续用例。
- 条件只能比较参数与固定 JSON 值，compute 不支持比较表达式；无法直接声明 `USER_B != USER_A` 的去重分支。正常清理顺序通过 HTTP 失效探测避免同 ID 重复注销；若 A 注销失败且重复注册又错误返回同 ID，B 探测断言报告清理失败，但 finally 继续执行仍可能再次尝试注销此 ID。这是异常清理分支的精确覆盖缺口，不能将其报告为完全符合“同一 ID 只注销一次”。
- 注册响应丢失、缺少 ID 或凭证时不能证明无账号残留；必须人工记录清理未确认并停止环境复用。XML 无法凭空恢复未知用户凭证。

## HTTP 接口缺口

- 公开 HTTP 只有社区列表，无创建社区接口；无可用社区明确 Blocked，不能把前提查询成功算作场景通过。
- 没有公开用户总量/按身份查询接口，不能直接证明数据库中用户总数；仅验证重复请求不返回新用户凭证、原账号可查询，与源用例 HTTP 观察范围一致。
