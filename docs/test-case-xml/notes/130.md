# TC-130 转换说明

- 来源：`docs/test-case/130-auth-missing.md`。唯一接口步骤为不携带 Authorization 的 `GET /me`，期待 HTTP 401、code=40101、data 不包含用户信息、requestId 非空、无业务数据写入。
- 步骤 10（目标断言）：`GET /me` 使用 `<auth mode="none"/>` 明确不发送鉴权（完全缺失令牌，不手写 Authorization 头），仅带 Accept: application/json，无 body/路径/查询绑定。断言真实 HTTP 401、业务码 40101、requestId 非空、响应键仅限通用信封（code/message/data/requestId）、data 为 None 或空对象（不含任何用户字段）、响应不携带 Authorization 凭证头。全部为目标断言，失败直接 assert（源用例目标为 401，返回 200 等即按失败记录）。
- 步骤 20：重复一次相同缺失令牌请求，确认被持续拒绝且依旧无凭证签发；该步骤末尾 raise Blocked，标记源用例「无业务数据写入」要求。未注册账号时没有任何公开 HTTP 查询接口（无匿名用户列表/业务数据查询）能观察服务端写入副作用，按源用例「没有 HTTP 查询能力的内部存储…不计为已验证」记录为阻塞；响应不泄露用户信息、不签发凭证仅为间接佐证。
- 本用例不注册用户、不创建任何业务数据，无需 finally 注销或清理。
- 阻塞/无法表达项：
  - XML 格式无法表达：无。本用例仅两个 main 步骤，全部落在 XSD 表达范围内。
  - 业务接口缺口：「无业务数据写入」缺乏公开 HTTP 观察路径（不存在匿名用户/业务数据查询接口），XML 以步骤 20 raise Blocked 标记，执行结论应按源用例记录「已核查 401/code/data/requestId，写入副作用范围阻塞」。
- 契约依据：`src/main/resources/rest-api/users.yaml` 的 GET /me（bearerAuth 保护，仅声明 200，未声明 401 响应）；实现 `UserRepository.authenticate` 对缺失/空白 Authorization 抛出 `ApiException.unauthorized("未登录")`，`ApiExceptionHandler` 映射为 HTTP 401/code=40101/data=null；`RequestIdFilter` 保证 requestId 非空。断言按源用例目标验证真实 HTTP/业务码。
- 清理说明：无 finally；本用例不持有令牌、不创建账号。调度方仍须按共享身份规则串行执行，任务终态为 blocked 时按约定停止后续任务。
- 可表达性结论：源用例主体（401/code=40101/data 不含用户信息/requestId 非空）完整可表达；「无业务数据写入」因业务接口缺口以最后一步 Blocked 记录。
- 仅生成；未执行 HTTP、部署或数据库操作。XSD/语义及真实导入器离线校验结果见交付简报。
