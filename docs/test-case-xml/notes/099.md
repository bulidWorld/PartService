# TC-099 转换说明

- 来源：`docs/test-case/099-chat-pagination.md`。独立查询社区、注册 A（邮箱 782213745@qq.com）/B（手机号 13900000002）、A 创建主题并邀请、B 接受入群、A 连发 M1/M2/M3 三条消息，再以 B 身份按 limit=2 与 before 游标分页查询消息历史，验证游标翻页。
- 步骤 1-3（社区、双注册）与步骤 4-9（主题、邀请、接受、三条消息）均为业务准备，断言失败 raise Blocked 并停止后续业务、进入 finally；M2/M3 发送步骤分别以 ifParameter M1/M2 + onFalse="blocked" 链式依赖前序提取的消息 ID，任何准备失败均不进入分页断言。
- 步骤 10（首页）：GET /rooms/{roomId}/messages?limit=2（TOKEN_B），断言 items 恰为 [M3, M2]（最近两条在前、页内顺序稳定且 M1 被排除）、hasMore=true；提取 data.items[1].id → BEFORE（本页最早消息 ID）、data.items → PAGE1_ITEMS。BEFORE 直接取本页最早消息 ID，与源用例一致，不依赖 nextCursor 取值。
- 步骤 11（翻页）：GET /rooms/{roomId}/messages?limit=2&before=BEFORE（TOKEN_B），断言 items=[M1]、两页 ID 无重叠、两页并集={M1,M2,M3}、hasMore=false、nextCursor=null；若游标被忽略，第二页会重现 [M3, M2]，断言即失败。首页 hasMore=true 与末页 nextCursor=null 源用例未明说，按 Page schema 语义与 089 先例补充；页内顺序约定（最新在前）依据“首页取最近两条消息”及 before 向前翻页语义推导，源文档未显式写出。
- 阻塞/无法表达项：
  - XML 格式无法表达：清理失败后跨任务停止调度无法由单个 XML 表达，须由调度方串行复用共享身份，任一用户清理失败/未确认即停止环境复用；源用例“执行记录”表（HTTP/业务码、requestId、结论）属执行期记录，由执行器填写，XML 不承载。
  - 业务接口缺口：无。本用例全部步骤（含 before/limit 查询参数与清理核查）均有公开 HTTP 接口可观察，未引用数据库、日志或内部存储。
- 清理说明：finally 依次清理 B/A，每用户先 GET /me 探测（200/code=0 且 id 匹配；401/code=40101 时用 refreshToken 调 POST /auth/refresh 并以 updateParam 覆盖 TOKEN/REFRESH），再 DELETE /me 断言 200/code=0/data={}/非空 requestId 并提取业务码与 requestId 供记录，随后用注册时保存的原始令牌与最新令牌分别 GET /me、POST /auth/refresh，均断言 401/code=40101；每步带 ifParameter 条件，单步失败不阻断其他清理；只清理本用例实际创建的用户，401 不代表账号已删除。
- 可表达性结论：XSD/导入器可表达本文件全部流程；OpenAPI（rooms.yaml）声明了 limit/before 查询参数，请求绑定与断言字段均来自接口契约与通用信封（code/message/data/requestId）。备注：当前 RoomsControllerImpl.listMessages 未按 before/limit 过滤（返回全量且 hasMore=false），若执行前服务未实现分页，步骤 10/11 将如实失败，这正是本用例的检测目标，不调整断言。
