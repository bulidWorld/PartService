# TC-079 转换说明

- 源：`docs/test-case/079-topic-automatic-distribution.md`。独立查询两个不同社区，A/B 注册在社区 A，C 注册在社区 B，A 创建无性别/年龄限制主题；不调用人工邀请接口。B/C 各执行一次 pending、limit=20 收件查询，提取实际 items 与 hasMore，检查 HTTP 200、code=0、requestId 和收件响应结构。这些仅是前提及观察，不能作为自动推送目标通过。
- 明确 Blocked：源文档和公开契约尚未明确自动推送与可接受/拒绝 invitation 的映射，也没有配置的推送完成 SLA 数值或公开查询配置接口。最后一次 C 收件断言检查响应后无条件抛出 Blocked，仍保留返回数据供脱敏记录。B 应收到、C 不应收到、全部匹配用户覆盖、可操作性及 SLA 内完成均未验证；不能用人工邀请或后台造数替代。没有臆造等待时长，两个查询只是初次观察，不冒充源要求的 SLA 内轮询。
- XSD 能表达 wait，却不支持循环/轮询，也不提供独立 Blocked 节点；因此在最后收件 HTTP 断言明确阻塞。契约确认后仍需补充真实 SLA、轮询能力及等待后过期凭证刷新，当前 XML 不宣称覆盖这些范围。
- 每次注册立即提取用户 ID、访问/刷新令牌及原始令牌备份，断言失败也发布；finally 按 C/B/A 探测 GET /me，过期才刷新更新清理凭证，逐个 DELETE /me 并断言 HTTP 200、code=0、data={}、非空 requestId，逐个核查原始和最新访问/刷新令牌均 HTTP 401、code=40101。单个清理失败仍继续其他用户清理。社区或注册前提失败明确 Blocked，不删除已有未知用户。
- 清理失败、响应丢失、凭证不足均记录为清理失败/未确认，不能单凭 401 推断账号已删除。跨任务停止调度无法由单 XML 表达，调度者须据 finally 结果停止后续任务和环境复用；共享邮箱/手机号必须串行。OpenAPI 尚未完整声明 GET /me、POST /auth/refresh 的 401/40101 错误模型，按源文档断言。
- 仅生成并离线校验，未运行 HTTP、未部署、未改数据库；使用现存 `docs/test-case-xml/task.xsd`，未恢复或修改源文档及 XSD。
