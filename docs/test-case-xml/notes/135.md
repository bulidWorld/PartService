# TC-135 转换说明

- 来源：`docs/test-case/135-pagination-invalid-cursor.md`。独立查询社区并注册用户 A（邮箱 782213745@qq.com、code 246810），随后带 TOKEN_A 请求 `GET /topics?status=open&limit=20&cursor=malformed-cursor`，目标断言 HTTP 400、code=40001，服务不得忽略错误游标当作第一页成功返回。
- 逐步骤转换：步骤 1 GET /communities 公开接口，无可用社区或 ID 不可取得时 raise Blocked，提取 `data[0].id → COMMUNITY_A`；步骤 2 POST /auth/register 绑定全部字段并按 Schema 校验，社区/注册准备失败 raise Blocked，断言失败仍提取 user.id/accessToken/refreshToken 供 finally 清理；步骤 3 GET /topics 用 queryParams 正常绑定 status/limit/cursor。cursor 在 OpenAPI 中为无 format/pattern 约束的 string，`malformed-cursor` 可通过 Schema 校验，无需 rawQuery 绕过，非法性由服务端业务校验拒绝；目标断言直接 assert 400/40001、非空 requestId/message，不用 Blocked。所有变量来自本文件前序响应。
- finally 清理 USER_A：先 GET /me 探测（200/code=0 且 id 匹配，或 401/40101），探测码为 40101 时先 POST /auth/refresh 并用 updateParam 更新 TOKEN_A/REFRESH_A；DELETE /me 断言 200/code=0/data={} 和非空 requestId，并提取业务码、requestId 供记录；随后逐一核查原始及最新访问/刷新令牌均返回 401/code=40101。每步带 ifParameter 条件，单步失败不阻断其他清理；401 不代表账号已删除。
- 阻塞/无法表达项：
  - XML 格式无法表达：md「清理失败/未确认时停止环境复用与后续用例」是跨任务调度语义，单个 XML 无法表达，须由调度器串行执行共享身份并在清理失败时停止；md「执行记录」表的结论文字与脱敏保存为人工/调度器职责，XML 仅提取 DELETE 业务码与 requestId 供记录，不记录令牌原文。
  - 业务接口缺口：无。社区列表、注册、主题分页列表、刷新、me 读写均有公开 HTTP 契约，本文件全部断言均可通过 HTTP 观察。
- 可表达性结论：源用例步骤 1~3 与清理流程全部可由 XSD/导入器表达，无被迫降级或跳过的步骤。
