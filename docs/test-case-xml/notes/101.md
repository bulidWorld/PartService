# TC-101 转换说明

- 来源：`docs/test-case/101-rating-good.md`。独立查询社区与评价分类、注册 A（email）与 B（phone）、创建主题、邀请并接受，A 对共同参与者 B 提交好评（score=good、categoryCodes=["reliable"]、comment="守信，沟通顺畅。"），随后用公开评价列表核对。
- 评价域此前无既有 XML，请求与响应字段以 `rest-api/ratings.yaml` 为准：`POST /topics/{topicId}/ratings` 响应 data 为 Rating（id/topicId/fromUserId/toUserId/score/categories/comment/createdAt）；`GET /rating-categories` 响应 data 为字符串数组；`GET /users/{userId}/ratings` 为公开分页接口（OpenAPI 未声明 security），data 为 Page（items/nextCursor/hasMore）。
- 步骤转换要点：步骤 1、2 为公开准备请求，社区不足或 reliable 分类缺失均 raise Blocked（无公开创建社区/分类接口）；步骤 8 分类复核同样 Blocked。注册 A/B、主题、邀请、接受为准备请求，失败 raise Blocked，断言失败仍提取 user.id/accessToken/refreshToken 供 finally 清理。提交好评与公开列表为目标断言，直接 assert：提交响应核对 fromUserId=USER_A、toUserId=USER_B、topicId=T、score=good、categories 含 reliable；列表 limit=20 且恰好一条，核对 id 与提交响应提取的 RATING_ID 一致、categories 与 comment 与提交内容一致、hasMore=False。
- 共同参与者身份通过 A 创建主题、邀请 B、B 接受产生聊天室（roomId 为非空 UUID）建立，仅 HTTP 可观察；评价请求本身不携带 roomId，参与关系由服务端按主题参与校验，本文件不推断内部参与存储。
- finally 顺序清理 B、A：先 GET /me 探测，40101 时 POST /auth/refresh 并 updateParam 更新当前访问/刷新凭证；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码及 requestId 用于记录；逐一核查注册原始及当前访问/刷新凭证 HTTP 401/code=40101。单步失败仍继续其他清理；401 不代表账号已删除。
- XML 格式无法表达：跨任务身份互斥与清理失败停止后续用例需执行器任务组策略；共享邮箱/手机号必须串行复用，清理失败或未确认时停止环境复用，并保留各 HTTP/业务码与 requestId 脱敏记录。
- 业务接口缺口：无。源用例要求均可由公开 HTTP 覆盖；社区/分类不足时按源用例记录阻塞。不核查内部存储、广播或日志。
- XSD/语义及真实导入器离线校验通过（0 errors）。仅生成；未执行 HTTP、部署或数据库操作。
