# TC-139 转换说明

- 来源：`docs/test-case/139-audit-log-redaction.md`。源用例主题为完整业务链路审计与敏感信息脱敏，头部执行条件即为「阻塞：缺少 HTTP 接口」；仅核查公开契约可访问的接口，不能验证日志内容与脱敏。
- 逐步骤转换要点：
  - 源用例步骤 1 声明公开契约没有访问日志或审计记录的 HTTP 查询接口，只能检查响应体。核对全部六个 OpenAPI 文件（auth/users/topics/invitations/rooms/ratings）确认无 audit/log 相关接口，因此未虚构任何查询接口。
  - 源用例步骤 2（`GET /communities`）转换为 taskStep 10：公开接口探针，auth mode=none，断言 HTTP 200/code=0、requestId 非空、data 为数组；探针失败按「准备请求失败」raise Blocked。
  - 源用例步骤 3（结论为阻塞）转换为 taskStep 20：复用只读、公开、幂等的 `GET /communities` 作为 Blocked 载体（assertionCode 只允许出现在 rest 步骤内），重复核查响应后 raise Blocked，终态 blocked。按源用例期待结果，requestId 正确不能证明后台日志满足审计完整性与脱敏要求，不在任何断言中声称通过。
  - 本用例不注册用户、不创建业务数据，故省略 finally，不执行任何清理。
- 阻塞/无法表达项：
  - 业务接口缺口：源用例目标本身需要访问日志/审计记录查询接口，公开契约没有该能力；转换以最后一步 raise Blocked 落盘原因，未虚构接口，也未把探针成功记为目标场景通过。日志内容与敏感信息脱敏完全无法通过公开 HTTP 核查。
  - XML 格式无法表达：源用例头部元数据（优先级 P1、执行条件「阻塞：缺少 HTTP 接口」、执行记录表格）在 task.xsd 中无对应字段，由 task name 与本文档承载。
- 可表达性结论：可表达部分为公开接口探针（HTTP/业务码/requestId/data 形态）与「目标无法验证」的阻塞结论；不可表达部分为审计日志查询与脱敏核查本身（接口缺失）。XSD/导入器可表达本文件全部流程。
- 仅生成；未执行 HTTP、部署或数据库操作。XSD/语义及真实导入器离线校验结果见交付简报。
