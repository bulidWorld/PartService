# TC-122 转换说明

- 来源：`docs/test-case/122-risk-insufficient-samples.md`。独立查询社区与评价分类，注册 A（email 782213745@qq.com）/B（phone 13900000002），A 创建主题并邀请 B，B 接受形成聊天室，A 对 B 提交一条 good 评价（categoryCodes=["reliable"]），随后以 B 的令牌查询 `/me/rating-summary`，验证少量评价不能触发系统评级。
- 逐步骤转换要点：
  - 步骤 1：GET /communities 为公开接口，取 data[0].id 存 COMMUNITY_A；无社区即 raise Blocked，因公开 HTTP 无社区创建接口，不写死或臆造 ID。
  - 步骤 2：GET /rating-categories 为公开接口，检查 data 数组包含 reliable 编码，缺失 raise Blocked；不创建或修改分类。
  - 步骤 3-4：注册 A/B，保存 data.user.id、data.accessToken、data.refreshToken 及原始凭证副本（TOKEN_X_ORIGINAL/REFRESH_X_ORIGINAL）；断言失败仍提取参数供 finally 清理，避免误删来源不明的已有身份。
  - 步骤 5-7：A 创建主题（genders=[]）、邀请 B、B 接受邀请；roomId 按 8-4-4-4-12 十六进制 UUID 格式校验。
  - 步骤 8：POST /topics/{topicId}/ratings 提交 good 评价，断言回显主题、双方用户、评分、分类与评论。
  - 步骤 9：GET /me/rating-summary（TOKEN_B）断言本文件唯一一条评价已落入摘要（good_count=1、neutral_count=0、bad_count=0、total_count=1）且 risk_tags 为数组；这些均为公开 HTTP 可观察事实。
- 阻塞/无法表达项：
  - 业务接口缺口：源用例执行条件为「待算法规则确认」，最小收评样本量 N_in 与最小发评样本量 N_out 阈值规则无公开算法配置查询接口，risk_tags 应为空数组及「一条好评不误标新用户」均依赖未确认规则，不猜测，步骤 9 末尾 raise Blocked 记录阻塞（已核查的摘要计数断言仍生效）；无社区/分类创建接口，前提不足即 Blocked；OpenAPI 未声明 GET /me、POST /auth/refresh 的 401 响应与错误信封，清理失效核查按源用例要求断言真实 HTTP 401/业务码 40101。
  - XML 格式无法表达：清理失败须由调度器停止后续任务、共享身份串行执行属跨任务调度约束，单 XML 无法表达；执行记录表格（环境版本、时间、实际 HTTP/业务码、requestId、结论）由执行方填写。
- 清理说明：finally 按源用例顺序先 B 后 A。每用户先 GET /me 探测（200/code=0 且 data.id 匹配；401/code=40101 则先 POST /auth/refresh 并用 updateParam 更新当前访问/刷新令牌），DELETE /me 断言 HTTP 200/code=0/data={} 与非空 requestId，并提取业务码/requestId 供记录；随后原始访问令牌与当前访问令牌 GET /me、原始与当前刷新令牌 POST /auth/refresh 均断言 HTTP 401/code=40101。每步带 ifParameter 条件，单步失败不阻断后续清理；401 不代表账号已删除。
- 可表达性结论：除风险评级算法规则判定（待算法规则确认）与跨任务调度约束外，XSD/导入器可表达本文件全部流程。
