# TC-081 转换说明

- 来源：`docs/test-case/081-chat-message-retry.md`；生成 `081-chat-message-retry.xml`。仅生成与离线校验，未运行 HTTP、部署或修改数据库。
- 完整独立准备：查询社区、注册 A/B、创建主题、邀请并接受，房间校验为非空 UUID；准备失败或社区不足明确 Blocked。注册响应立即提取用户 ID、访问/刷新令牌，断言失败仍提取供清理。
- 业务覆盖：A 连续两次发送相同 clientMessageId 与相同消息体，检查真实 HTTP 200、业务 code=0、requestId，重试返回相同消息 ID 和 createdAt；B 的消息历史按 clientMessageId 计数必须恰好一次，且 ID、时间、房间、发送者、正文、类型、元数据、撤回标记一致。新建独立房间的历史还须没有后续页。
- finally 按 B、A 逐个 GET /me 探测，令牌失效时刷新并更新清理凭证，DELETE /me 检查 HTTP 200、code=0、data={}、非空 requestId；随后逐一核查原始及最新访问和刷新令牌均 HTTP 401、code=40101。清理单步失败仍继续其他步骤及账号。
- HTTP 可观测要求均有契约支持；广播次数、内部存储与日志不计为已覆盖。无需 raw*，无阻塞目标验证的接口或 XSD 缺口。OpenAPI 未完整列出 GET /me、POST /auth/refresh 的 401 响应体，XML 依源用例明确断言 401/40101，不弱化失效核查。
- XSD/执行器限制：单 XML 不能停止跨任务调度；共享邮箱/手机号须串行复用，任何清理失败或未确认必须由执行方停止后续环境复用。账号创建但响应丢失或凭证缺失时，不可仅凭 401 推断已删除，记录清理未确认。执行记录应保留逐步骤真实 HTTP/业务码、requestId 和结论并脱敏，不保存令牌原文。
- 校验：`validate.py` 及真实导入器 `validate_importer.py --importer-root /opt/apps/Deployment/AutoTestService` 均通过（1 XML / 0 errors）；离线转换与配置校验，不连接 DB/HTTP。
