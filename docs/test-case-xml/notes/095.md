# TC-095 转换说明

- 来源：`docs/test-case/095-chat-recall-idempotent.md`。独立查询社区、注册 A（邮箱 782213745@qq.com）与 B（手机 13900000002）、A 建主题并邀请 B、B 接受进入同一聊天室、A 发消息后以同一令牌连续两次 POST `/rooms/{roomId}/messages/{messageId}/recall`。
- 两次撤回均按 OpenAPI 声明的 200 MessageResponse 断言 HTTP 200/code=0、data.id=M、recalled=true、senderId=USER_A、createdAt 与发送响应提取的 M_CREATED_AT 一致。源用例未给出 409 冲突等替代可接受响应，服务实现（recall 重建消息并保留原 createdAt/roomId/senderId）亦为幂等 200，故未按多可接受集合书写。首次撤回成功是重复撤回场景的前提，失败 raise Blocked；第二次撤回及历史比对为直接目标断言。
- 目标判定全部通过公开 HTTP 查询完成：首次撤回后以 B 令牌 GET `/rooms/{roomId}/messages` 保存整页快照 AFTER_FIRST（数量 1、hasMore=false、recalled=true、content/createdAt/senderId 与发送响应一致），第二次撤回后再次查询并断言数量、id、recalled、senderId、createdAt 不变且整页等于 AFTER_FIRST，覆盖源用例「两次均保持同一消息 recalled=true；记录数量、原 createdAt、senderId 不变」。
- 所有变量来自本文件前序响应；社区不足或注册、主题、邀请、接受、首次撤回等准备失败均 Blocked；断言失败仍提取参数，finally 清理本次实际创建的账号，不删除来源不明的已有身份。
- finally 按源用例顺序清理 B/A：先 GET /me 探测（200 校验 id 匹配，40101 时先刷新并用 updateParam 更新当前访问/刷新凭证），DELETE /me 断言 HTTP 200/code=0/data={}/非空 requestId 并提取业务码与 requestId 供记录；再分别以注册签发的原始令牌与最新令牌核查 GET /me 及 POST /auth/refresh 均为 HTTP 401/code=40101。每步带 ifParameter 条件，单步失败不阻断后续清理；401 不代表账号已删除。
- 无法表达项：
  - XML 格式无法表达：清理失败或未确认时须由调度器停止后续任务、共享身份串行复用环境，单 XML 无法表达，须由调度方保证；执行记录表格由执行者事后填写。
  - 业务接口缺口：无。源用例的全部判定依据（两次撤回响应、消息列表查询）均有公开 HTTP 接口。
- XSD/导入器可表达本文件流程，无阻塞项。仅生成；未执行 HTTP、部署或数据库操作。XSD/语义及真实导入器离线校验结果见交付简报。
