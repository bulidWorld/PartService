# TC-105 转换说明

- 来源：`docs/test-case/105-rating-self.md`。独立准备社区与评价分类（分类必须含 reliable）、注册 A/B、A 创建主题并邀请 B、B 接受形成共同参与前提；随后 A 以 `toUserId=USER_A`（本人且为主题发布者）提交好评，目标断言必须 HTTP 400、code=40001。
- 为落实源用例「无评价或统计新增」且仅用公开 HTTP 可观察口径：目标请求前先快照 `GET /users/{USER_A}/ratings`（公开接口）与 `GET /me/rating-summary`（A 令牌），分别保存 RATINGS_BEFORE、SUMMARY_BEFORE；负向请求后再次查询两接口，断言与快照完全一致且列表无 topicId=T 的评价。快照对比是源文件未写明的前后置步骤，属实现「无新增」判定的必要转换。
- 「统计新增」仅存在被评者（toUserId）视角的公开查询；给出评价（fromUserId）一侧无公开列表接口。本用例 from=to 同为 USER_A，缺口不阻碍断言；评价内部存储、广播、日志不计为已验证。
- 无社区、分类缺 reliable、注册/主题/邀请/接受等准备失败均 Blocked；注册断言失败仍提取 user.id/accessToken/refreshToken，finally 只清理本次实际创建的账号，不删除来源不明的已有身份。所有变量来自本文件前序响应。
- finally 按源顺序先 B 后 A：GET /me 探测，40101 时刷新并更新当前凭证；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码与 requestId 供记录；逐一核查原始及最新访问/刷新令牌 HTTP 401/code=40101。单步失败仍继续其他清理；401 不代表账号已删除。
- XSD/导入器可表达本文件流程。OpenAPI（ratings.yaml）仅声明评价提交的 200 响应，未声明 400/40001；断言按源用例要求的真实 HTTP/业务码验证。清理失败跨任务停止调度无法由单 XML 表达，调度方须串行复用共享身份，清理失败或未确认立即停止环境复用；执行记录登记真实 HTTP/业务码、requestId 与清理结论并脱敏，不保存令牌原文。
- 仅生成；未执行 HTTP、部署或数据库操作。XSD/语义及离线校验结果见交付简报。
