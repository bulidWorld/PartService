# TC-097 转换说明

- 来源：`docs/test-case/097-chat-wrong-room-read.md`。生成独立同 stem XML，社区从本文件 `GET /communities` 提取；注册 A（email 782213745@qq.com）与 B（phone 13900000002），A 创建两个主题并邀请 B、B 接受得到 ROOM/ROOM2，A 在 ROOM 发送消息 M。目标：A 以 M 对 ROOM2 调用 `POST /rooms/{roomId}/read`，必须 HTTP 400/404 且业务码非 0。
- 逐步骤转换要点：所有 REST 显式 auth（公开接口 none、业务接口 bearer）、写 Accept，JSON 体加 Content-Type；每次响应断言真实 HTTP 状态、业务 code、非空 requestId；roomId 校验 UUID 且 ROOM2 != ROOM。步骤 110/120 由成员 A 先快照 ROOM2 聊天室与空消息页，130 发目标负向请求，140/150 核对快照完全一致、160 核对 ROOM 中 M 原封未动（recalled=false、正文/roomId/senderId 不变、仅一条），证明无消息移动/删除副作用。
- 目标负向断言：statusCode in (400, 404)、code != 0（源用例只承诺业务码非 0，不写死 40001/40401）、data 仅 null/{}、信封键恰为 code/message/data/requestId；错误 message 不得包含消息正文、双方昵称或用户 ID（可观察的隐私泄漏范围）。目标断言失败直接 assert；准备失败一律 raise Blocked 并进入 finally。
- 业务接口缺口（阻塞项）：
  - ReadPosition 只有 `POST /rooms/{roomId}/read` 的写入响应，没有 GET 已读位置接口，Room 也无已读位置字段；不能通过重复写入冒充读取核查，也不能用数据库/日志替代。完成可观察断言后最后一步（170）raise Blocked，不将部分覆盖记为整例通过，不臆造查询接口。RoomsControllerImpl.markRoomRead 当前只回显请求参数（静态阅读，未执行）。
  - 无社区创建 HTTP 接口，社区不足即 Blocked；OpenAPI 未声明 read 的 400/404 及多数鉴权 401 响应，按源用例断言，不改源契约。
- XML 格式无法表达：单 XML 不能控制跨任务停止调度；共享邮箱/手机号必须由调度方串行执行，清理失败/未确认时调度方停止后续任务及环境复用。执行记录/脱敏记录由执行者人工填写，不保存令牌原文。
- 清理说明：finally 按 B/A 逐用户：GET /me 探测（200/code=0 且 id 匹配，或 401/code=40101），探测到 40101 时先 POST /auth/refresh 并用 updateParam 更新 TOKEN/REFRESH；DELETE /me 断言 200/code=0/data={}/requestId；随后原始及最新访问/刷新令牌逐一核查 HTTP 401/code=40101。每步带 ifParameter，单用户单步失败不阻断其他清理；401 不代表账号已删除。所有令牌参数 sensitive="true"，仅清理本用例创建的用户。
- 可表达性结论：XSD/导入器可表达本文件主流程、负向断言与完整清理；仅「不得把 ROOM 消息记为 ROOM2 已读位置」因无公开查询接口阻塞（raise Blocked 收尾）。
- 仅生成并离线校验（validate.py：1 XML / 0 errors；validate_importer.py 本环境缺 openapi_spec_validator 依赖未能运行）。未运行 HTTP、未部署、未改数据库。
