# 用例 029 生成说明

- 昵称：md 要求"测+UUID 去连字符前 12 位"，compute 无 substring/去连字符截取能力 → 改为固定昵称（每个角色一个，昵称允许重复）。
- 验证码 code：compute 无随机数字函数 → 固定 "123456"（测试环境已关闭邮箱验证码校验）。
- 断言沙箱禁止 re，社区条目 id 的 UUID 格式只断言非空（与 002 样例同风格）。
- SQL 参数绑定：md 的 :user_id 改写为 %s 占位符 + <parameter>a_id</parameter>；表名 "user" 按 md 原文使用（resources/db 不在仓库，未核实）。
- "早于当前 UTC 时间七天"：断言沙箱无 datetime 解析 → 在 SQL 更新之后的 compute（timezone="UTC"）生成阈值 isoformat(add_seconds(now(), -604800))，断言 communityChangedAt 字符串 < 该阈值且 != 注册响应提取的 reg_changed；ISO-8601 字符串按字典序比较即时间序（偏移恒定），SQL 时刻比阈值早至少 2 秒保证前缀不同、比较稳定。
- "本次调用附近时间"：断言切换后 communityChangedAt > 阈值 seven_ago 且 != SQL 后读取的 old7，配合 PATCH 本身返回 200 验证冷却重置；随后 PATCH 回 C1 按 md 断言 409/40901。
- 双社区前提：GET /communities 不足 2 项 raise Blocked；PATCH C2 步骤 ifParameter="c2" onFalse="blocked"。
- 清理：本例不创建主题/聊天室（或失败发布不建房），md 清理第 1/5 步"无聊天室则跳过"，故省略 GET /rooms 补录与 chat_room 的 SQL 清理。
