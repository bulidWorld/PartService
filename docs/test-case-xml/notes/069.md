# 用例 069 生成说明

- 六位随机数字验证码：compute 无随机数字函数，`code` 固定 "123456"（环境已关闭验证码校验）。
- 昵称规则"测+UUID 去连字符前 12 位"：无 substring 函数，A/B 用固定昵称 "测069甲"/"测069乙"（昵称允许重复）。
- 收件查询"每秒重试最多 30 秒"：用 rest 内 `<poll maxAttempts="30" intervalMilliseconds="1000" timeoutSeconds="30"/>` 表达。
- clientMessageId 为 65 个 "k"，超出 Schema maxLength=64：请求体改用 rawBody（CDATA 原文 JSON，不插值），并声明任务级固定参数 `long_id`（同值）供历史查询断言引用（rawBody 字面量与 long_id 值保持一致）。
- md 步骤 6 生成 K 但步骤 7 使用固定超长字面量，K 按 md 保留生成但未参与请求。
- 历史查询"无本次失败请求的消息"：断言 items 中 clientMessageId==long_id 的条数为 0。
- 错误响应"不能出现堆栈/SQL/凭证"：用 message 不包含 Exception/SQL/SELECT/password 近似表达。
- finally 第 1 步"GET /rooms 按主题 ID 筛选补录 roomId"：extractParam 无过滤表达式，无法真正补录；改为断言本例主题 T 对应房间 ID 与 R 一致（R 缺失时仅放行），SQL 清理由 ifParameter="R" 守卫，accept 未取得 roomId 时聊天室可能残留。
- SQL 清理表名 chat_room 按 md 原文使用；resources/db 不在仓库，表名与列名未核实。
