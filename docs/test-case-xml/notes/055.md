# TC-055 转换说明

- 源：`docs/test-case/055-topic-expiration.md`；产物：`055-topic-expiration.xml`。只生成与离线校验，未运行 HTTP、未部署、未改数据库。
- 独立执行：查询社区并提取真实 ID，注册邮箱用户 A / 手机用户 B；每次注册立即独立提取用户 ID、访问与刷新凭证，断言失败仍提取。共享身份必须串行执行。
- 运行时 UTC 计算 `isoformat(add_seconds(now(), 60))`，创建主题并邀请 B，保存主题、邀请与房间 ID；使用动态 wait 等到 EXPIRES 后 1 秒。1 秒只用于确保越过时间点，不是臆造 SLA。
- 等待后分别刷新 A/B 凭证，再检查 expired、接受邀请 HTTP 409/code 40901、open 列表排除主题。新增公开 GET /rooms 与 GET /rooms/{roomId}，比较唯一房间成员始终仅 A，核查无新增成员。最后再取详情核查 expired 及原 createdAt、标题、详情，作为历史保留的 HTTP 可见证据。

## 阻塞与缺口

- 源用例没有约定到期处理 SLA，不能编造 SLA。到期首次详情若尚未 expired，明确 Blocked，后续业务步骤不执行；若已经 expired，则继续业务核查，最终详情断言仍明确 Blocked，表示时效验收未覆盖。任何已执行业务断言失败仍作为失败，不以 Blocked 覆盖。
- XSD wait 没有 HTTP 轮询循环；缺少 SLA 上界也无法构造忠实有界轮询。本 XML 实现一次越过到期时刻后的观察，不声称完成 SLA 内轮询验收。需要给出 SLA 并补充执行器轮询能力后再完成时效验收。
- 房间列表按公开契约没有 cursor 入参。独立环境仅本主题房间，准备断言要求仅一项、topicId 匹配且 hasMore=false，否则 Blocked，避免从不完整列表推断成员。
- OpenAPI 未列 accept 的 409 错误响应业务结构，但源明确要求 HTTP 409/code 40901，XML 保留严格断言，不降低为 200。
- 只以 HTTP 详情仍存在证明历史记录保留，不声称验证内部存储、日志或广播。

## 必执行清理

finally 按 B、A 顺序逐个探测 GET /me；仅访问令牌过期（40101）时刷新并更新清理凭证，再 DELETE /me，严格检查 HTTP 200/code 0/data={}/非空 requestId。随后分别检查注册、等待后刷新、清理刷新签发的所有访问与刷新令牌均 HTTP 401/code 40101。某用户清理失败仍尝试其余用户，不能将 401 推断为账号已删除。清理步骤记录响应码与 requestId，敏感凭证标记脱敏。

单 XML 无法禁止后续任务调度；执行器必须保证任一清理失败/未确认后停止当前环境后续任务与共享身份复用。
