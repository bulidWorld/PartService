# 用例 091 评价汇总数量和比例

- 六位随机验证码 code：compute 无随机数字函数，按环境已关闭邮箱验证码校验的约定固定为 "123456"。
- 昵称按"测+UUID前12位"规则生成需要 substring，compute 不支持；改为固定昵称（每角色一个），昵称允许重复。
- 清理时"先用有效令牌 GET /rooms 按主题 ID 筛选补录 roomId"的回退无法表达：提取表达式不支持按 topicId 过滤，无法安全补录；仅依赖 accept 响应提取的 roomId，缺失时 SQL 清理步骤因 ifParameter 守卫自动跳过（不得全表清理）。
- SQL 清理表名 chat_room 按 md 原文使用，resources/db 不在仓库，未核实。
- 推送异步分发：GET /topics/receipts 用 rest/poll（maxAttempts=30、intervalMilliseconds=1000、timeoutSeconds=30）实现"每秒真实等待重试最多 30 秒"。
- 注销按 md 顺序逐角色 DELETE /me（断言 200/code=0/data={}）后跟 GET /me 断言 401/40101，两步均以对应 accessToken 参数加 ifParameter 保护。
- 四角色：A 发布，B/C/D 接受（各自 receipts 轮询+accept，roomId 分别存 r_id/r2_id/r3_id）。
- 汇总接口 /me/rating-summary 用 rest/poll 30 次×1s 等待统计最终一致（"不会一直返回空汇总"）。
- good_rate/bad_rate 断言 abs(x-1/3)<=0.0001（"约1/3"），good/neutral/bad_count 各 1、total_count=3。
- categoryCodes 需为单元素动态数组（[${category}]）：compute 无数组构造表达式，采用 JSON Pointer 绑定 <key>/categoryCodes/0</key><parameter>category</parameter> 生成 {"categoryCodes":[category]}。
