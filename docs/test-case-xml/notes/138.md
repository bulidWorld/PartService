# TC-138 转换说明

- 来源：`docs/test-case/138-request-id.md`。独立准备社区、注册用户 A（邮箱 782213745@qq.com），随后带 `X-Request-Id: case-request-id-001` 请求头与不带该头各调用一次 `GET /me`，仅以 HTTP 响应判定请求链路 ID 的自动生成与透传。
- 逐步骤转换：步骤 1 `GET /communities`（公开）提取 COMMUNITY_A（data[0].id），无社区或 ID 不可取得时 Blocked；步骤 2 `POST /auth/register` 注册 A，失败 Blocked 并停止业务，断言失败仍提取 user.id/accessToken/refreshToken 及原始副本供 finally 清理与失效核查；步骤 3（目标）`GET /me` 显式带 `X-Request-Id: case-request-id-001` 请求头（非保留头，header 直接声明），断言真实 HTTP 200/code=0、响应体 requestId 与响应头 x-request-id 均为 case-request-id-001；步骤 4（目标）`GET /me` 不带该头，断言响应体 requestId 为非空字符串且与响应头 x-request-id 一致（服务端自动生成）。每步均断言通用信封 code/message/data/requestId 四键齐备、不存在旧文档 request_id 字段；响应头一致性通过断言函数 headers 参数（小写 x-request-id → 字符串列表）核对，无需读取日志或内部存储。
- 「不指定时均返回同一个非空 ID」按“同一响应内响应体 requestId 与 X-Request-Id 响应头相同且非空”理解，逐请求断言一致性；源用例未要求跨请求复用同一 ID，因此不断言步骤间 ID 相等或自动生成 ID 的具体格式。
- 失败语义：社区查询与注册为业务准备，失败 raise Blocked（终态 blocked，仍执行 finally）；步骤 3/4 为目标断言，失败直接 assert。所有变量来自本文件前序响应。
- finally 顺序清理 A：先 GET /me 探测（200/code=0 且 id 匹配；401/code=40101 时 POST /auth/refresh 并用 updateParam 覆盖当前访问/刷新凭证）；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码及 requestId 供清理记录；随后分别用原始与最新访问令牌 GET /me、原始与最新刷新令牌 POST /auth/refresh 核查 HTTP 401/code=40101。每步带 ifParameter 条件，单步失败继续其他清理；401 不代表账号已删除。
- 阻塞/无法表达项：
  - XML 格式无法表达：清理失败须由调度器停止后续共享身份任务，单 XML 无法表达，调度方须串行执行并核查清理结论；执行记录（脱敏响应、实际 HTTP/业务码、requestId、结论）由执行者维护，不在 XML 内。
  - 业务接口缺口：无。requestId 生成与透传均由响应体 requestId 字段及 X-Request-Id 响应头在公开 HTTP 层可观察，不需要数据库、日志、内部存储或服务重启。
