# TC-124 转换说明

- 来源：`docs/test-case/124-risk-recompute.md`；产物：`124-risk-recompute.xml`。源用例执行条件即为「阻塞：缺少 HTTP 接口」，结论为阻塞：没有公开重算同一批评级样本的 HTTP 接口，重复读取摘要不会触发已确认的重算流程，目标规则「相同样本重复计算不增加计数和评级」无法构造前提或核查结果。保留源用例唯一 HTTP 步骤 `GET /rating-categories`（无鉴权、Accept: application/json），核查响应为 HTTP 200/code=0、data 为分类编码字符串数组、requestId 非空后抛出 `Blocked`；查询准备失败同样阻塞，查询成功不代表目标场景通过。
- 评价提交（POST /topics/{topicId}/ratings）与摘要查询（GET /me/rating-summary）虽为公开接口，但只能观察已产生评级的计数与风险标签；源用例确认重复读取摘要不会触发重算流程，六个 YAML 也没有触发或重放评级样本的管理接口，无法在 HTTP 层构造「相同样本重复计算」的前提，也无法观察内部计数与评级是否因重复计算而增加。按源用例要求不尝试其他操作、不虚构 risk 相关接口，不以数据库、日志或内部存储替代断言。
- 阻塞与无法表达项，分两类：
  - 业务接口缺口：六个 rest-api YAML 均无触发评级重算或重放评级样本的接口，也无读取内部计算流水与计数明细的接口，前提构造与目标核查均无法通过公开 HTTP 完成。
  - XML 格式无法表达：跨任务「清理失败停止后续任务」由调度器实现，单任务 XSD 无此配置（本场景不创建用户、无清理，不涉及）。
- 清理说明：本场景不注册用户、不写入数据，省略 finally 清理。
- 可表达性结论：XSD/导入器可表达本文件流程（单 GET + raise Blocked 终态）。断言仅使用执行器白名单支持的 `isinstance`、`dict`、`list`、`str`、`all`、`assert` 与 `raise Blocked`。
