# TC-067 转换说明

- 来源：`docs/test-case/067-invitation-accept.md`。独立查询社区、注册 A/B、创建主题与邀请；接受邀请后立即用 B 查询聊天室，再查询双方列表。
- 检查接受结果 status=accepted、topicId=T、非空 UUID roomId；聊天室详情及双方列表指向同一 ROOM，A/B 各出现一次。列表要求无后页，避免缺失记录被分页掩盖。
- 所有 REST 显式鉴权及真实 HTTP/业务码断言。社区不足或注册/主题准备失败明确 Blocked，不将准备查询成功算作目标通过。
- 注册响应立即独立提取账号及访问/刷新凭证，断言失败亦保留；finally 逐个处理 B/A，先探测 /me，必要时刷新更新清理凭证，DELETE /me 后检查原始和最新访问/刷新令牌均为 HTTP 401/code=40101。逐用户保存注销业务码及 requestId，实际 HTTP 状态由执行器步骤记录保留；记录应脱敏。
- XSD 可表达该场景，无目标 HTTP 接口缺失。OpenAPI 的 GET /me、POST /auth/refresh 未声明清理核查所需 401 错误响应，XML 显式断言 401/code=40101。无社区创建接口，社区前提缺失时阻塞。
- 只覆盖公开 HTTP 可观察一致性，未验证内部事务、广播、日志或存储。单 XML 无法表达清理失败后停止跨任务调度；外部调度必须串行复用共享身份，任一清理失败/未确认时停止环境复用，不能凭 401 推断账号已注销。
- 仅生成与离线校验，未执行 HTTP、部署或数据库操作。
