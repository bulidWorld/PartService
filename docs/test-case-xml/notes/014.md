# TC-014 注册昵称超过 32 字符

- 来源：`docs/test-case/014-register-long-nickname.md`；输出：`014-register-long-nickname.xml`。
- 按现存 `docs/test-case-xml/task.xsd` 生成；原引用 `docs/task.xsd` 当前不存在。
- 当前为**可导入、明确阻塞**的用例。只执行公开 `GET /communities` 前提查询，无注册请求，不创建账号。查询失败或无社区时记录前提阻塞；有社区时仍明确报告 XSD 表达能力阻塞。不得把社区查询成功记作昵称边界场景通过。
- 源用例要求的负向注册、同身份有效注册、GET /me，以及意外成功账号和正常账号的 finally 注销/所有令牌失效核查，均保留于 XML 注释作为待恢复流程，尚不能执行，也不宣称已覆盖或通过。未创建账号时无清理对象。

## XSD / 执行器缺口

- **直接阻塞：动态原始请求体。** 注册契约 `RegisterRequest.nickname.maxLength=32`，目标 33 字符昵称必须使用 rawBody，避免导入/执行前 Schema 拒绝。正常注册要求 communityId 取自本次前序 HTTP 响应；而 XSD 明确规定 rawBody 不解析、不插值，只能是静态原始文本。不能同时使用 body 与 rawBody，故无法仅豁免昵称校验并继续绑定动态社区 ID。应增加动态原始 JSON 参数引用，或按字段禁用 Schema 校验的显式负向测试能力。不能写死 UUID、使用占位符原文或省略社区字段来假冒本场景。
- 跨任务串行复用邮箱、清理失败停止后续用例和环境复用、脱敏执行报告与逐用户清理结论需执行器保证，单个 task 不能约束其他任务。修复上述表达能力后需恢复完整 finally：立即保存两次注册可能创建的用户和两类令牌，必要时刷新，逐账号注销，并逐令牌核查 HTTP 401/code=40101；注销本身必须 HTTP 200/code=0/data={}、requestId 非空，不能把 401 当作已删除。

## HTTP 接口 / 实现缺口

- `UsersControllerImpl.listCommunities()` 当前固定返回空数组，且没有公开社区创建接口；在当前实现下第一步也会阻塞。此问题与动态 rawBody 的 XSD 问题独立。
- 无公开身份存在性预检接口，使用独立空测试环境；不得删除来源不明账号。
- OpenAPI 注册接口仅描述成功响应；HTTP 400/code=40001 的要求来自源测试。实现 `Requests.Register` 对 nickname 声明 `@Size(max = 32)`。
