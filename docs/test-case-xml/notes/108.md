# TC-108 转换说明

- 来源：`docs/test-case/108-rating-duplicate.md`。独立查询社区与评价分类，注册 A（邮箱 782213745@qq.com）/B（手机 13900000002），创建主题并邀请接受后，A 首次评价 B 得 good，重复提交得 bad 必须 HTTP 409/code=40901（业务冲突码来自 ApiException.conflict），公开列表仍仅一条原评价且 score/评论不变。
- 步骤 1 GET /communities 提取 data[0].id 到 COMMUNITY_A；步骤 2 GET /rating-categories 核对 data 含 no_show、reliable，缺少即 Blocked（不创建或修改分类）。步骤 3-4 注册 A/B 并保存 user.id、访问/刷新令牌（含 ORIGINAL 副本供失效核查）。步骤 5-7 建主题、邀请、接受，保存 T、I、ROOM（roomId 校验 UUID 格式）。
- 步骤 8 首次评价断言 data.id/topicId/fromUserId/toUserId/score=good/categories 含 reliable/comment 不变，并提取 RID；步骤 9 重复评价断言 HTTP 409、code=40901、data 为空、非空 requestId/message，且 message 不泄露双方身份与评论内容；步骤 10 GET /users/{userId}/ratings?limit=20 公开接口无鉴权，断言 hasMore=false、items 恰一条且 id=RID、topicId=T、fromUserId=USER_A、toUserId=USER_B、score=good、comment 为原评论。
- 业务接口缺口：源用例「统计只计数一次」无公开 HTTP 查询能力——`/me/rating-summary` 当前实现返回固定零值，无法观察真实计数，按「仅公开 HTTP 可观察」原则未虚构断言，最后一步完成可验证断言后 raise Blocked 说明原因。另注意列表响应中 categories 由持久化映射恒为空（RatingEntity 无分类列），故列表断言仅核对源用例要求的 score/comment 等字段，不断言 categories。OpenAPI 未声明评价 409 响应，断言按源用例明确的 409/40901 验证真实 HTTP/业务码。
- 准备失败均 Blocked；注册断言失败仍提取 user.id/accessToken/refreshToken，finally 清理本次实际创建的账号，不删除来源不明的已有身份。所有变量来自本文件前序响应。
- finally 顺序清理 B/A：先 GET /me 探测，40101 时刷新并更新当前访问/刷新凭证；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码及 requestId 用于记录；逐一核查原始及最新访问/刷新凭证 HTTP 401/code=40101。单步失败仍继续其他清理；401 不代表账号已删除。
- XML 格式无法表达：清理失败或未确认时由调度器停止后续任务无法由单 XML 表达，调度方须串行使用共享身份，清理失败立即停止环境复用；源用例执行记录表（脱敏手工记录）不在 XML 内；「统计只计数一次」要求以最后一步 Blocked 记录为阻塞。
- 仅生成；未执行 HTTP、部署或数据库操作。XSD/OpenAPI 离线校验结果见交付简报。
