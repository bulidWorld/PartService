- 源：`docs/test-case/076-invitations-isolation.md`。本 XML 独立获取社区、注册 A/B/C、由 A 创建主题并邀请 B；按 A/C/B 顺序查询 pending 收件列表，A/C 完整空页且不含邀请 I，B 唯一邀请为 I 并核对主题、邀请人与受邀人、pending 状态。
- 为源期待结果“不能通过省略筛选读取别人的邀请”，另以相同三用户省略 status 查询并重复隔离断言。完整页 hasMore=false、nextCursor=null，避免分页隐藏越权数据。在源要求的独立空环境下，A/C 无收件、B 唯一收件。
- 注册成功立即提取 user.id、accessToken、refreshToken，断言失败仍提取供清理。finally 按 C/B/A 探测 GET /me；过期才刷新并更新凭证，逐个 DELETE /me，检查 HTTP 200、code=0、data={}、非空 requestId，随后逐个验证最初及最新访问/刷新令牌 HTTP 401、code=40101。每个清理步骤失败不阻止其他用户清理。

- HTTP 契约与 XSD：公开接口足以表达业务范围，无业务覆盖缺口；OpenAPI 未完整描述 GET /me、POST /auth/refresh 的 401/40101 错误模型，清理按源要求显式断言。没有内部存储、日志或广播核查的覆盖声明。
