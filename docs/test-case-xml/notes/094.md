# TC-094 转换说明

- 来源：`docs/test-case/094-chat-recall-self.md`。生成独立同 stem XML，社区从本文件 GET /communities 提取；独立注册 A（邮箱 782213745@qq.com）/B（手机号 13900000002），A 创建主题、邀请 B、B 接受进入聊天室，A 发送消息后由 B 越权撤回、再由 A 撤回本人消息。所有 REST 显式 auth、真实 HTTP 状态/业务码断言，变量均来自本文件前序响应。
- 逐步骤转换要点：B（非发送者）撤回必须 HTTP 403/code=40301，错误响应 data 仅允许 null/{}、字段仅限 code/message/data/requestId，错误 message 不得包含消息正文及成员姓名/ID；A 撤回成功 HTTP 200/code=0，响应 data 断言 id/roomId/senderId/clientMessageId/messageType/content/contentMeta 不变、createdAt 与发送时一致、recalled=true。随后以 B 令牌查询完整消息页（limit=20）：断言仅一条消息、id 与正文/元数据/发送者/创建时间全部保留、recalled=true，即记录与顺序保留、撤回未被当作删除；当前实现 Message 撤回后仍保留 content，客户端应据 recalled 标志展示占位。
- 阻塞/无法表达项：
  - 业务接口缺口：源用例「客户端显示撤回占位」属客户端渲染行为，公开 HTTP 仅有消息列表 recalled=true 这一数据信号，无接口可观察实际占位渲染。已核查全部 HTTP 可观察断言后，最后一步 raise Blocked 说明该项无法验证，不将部分覆盖记为整例通过；不臆造客户端查询接口。另外公开 HTTP 无创建社区接口，无社区时注册及全部业务阻塞；OpenAPI 未声明 recall 的 403 和多数鉴权 401 响应，XML 按源要求断言真实状态码，不改源契约。
  - XML 格式无法表达：清理失败须由调度器停止后续任务、共享身份串行复用属跨任务调度约束，单 XML 无法表达，执行者须按源用例记录脱敏实际 HTTP/业务码、requestId、逐用户注销结论，清理失败/未确认时停止复用环境和后续任务。
- 清理说明：注册断言失败仍提取用户 ID、访问/刷新令牌和原始令牌副本，finally 按 B/A 逐用户 GET /me 探测（200/code=0 且 id 匹配；401/code=40101 时先 POST /auth/refresh 并 updateParam 覆盖 TOKEN/REFRESH），再 DELETE /me 断言 HTTP 200/code=0/data={}/requestId，随后用旧令牌 GET /me、旧/新 refreshToken POST /auth/refresh 逐一断言 HTTP 401/code=40101。每步带 ifParameter，单步失败不阻断后续清理；401 不代表账号已删除。
- 可表达性结论：除上述占位渲染观察与跨任务调度外，XSD/导入器可表达本文件全部流程与断言。
- 仅生成；未执行 HTTP、部署或数据库操作。离线校验 validate.py 结果见交付简报。
