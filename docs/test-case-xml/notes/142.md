- 源用例步骤 6-7（POST /topics/{T}/invite 邀请 USER_B、POST /invitations/{I}/accept 接受）在生成时点已与当前 OpenAPI 不一致：invitations.yaml 已删除、/topics/{topicId}/invite 已移除，参与模型改为主题推送与接受（见 `docs/requirements/03-topic-participation.md` 与 topics.yaml：POST /topics/{topicId}/accept、GET /topics/receipts、POST /topics/{topicId}/read）。转换按当前接口执行：B 直接 POST /topics/{topicId}/accept（无请求体、无需邀请 ID），断言收件 status=accepted、topicId 一致、roomId 为非空 UUID，同源用例「邀请接受产生同一 ROOM」等价。发布主题在同一事务同步生成推送收件，接受前无需等待。
- 步骤 1-4 准备：GET /communities 取第一项 id，不足或不可取得 Blocked（公开 HTTP 无社区创建接口）；GET /rating-categories 检查 data 包含 average、reliable，缺失 Blocked（公开 HTTP 无分类创建/修改接口）；注册失败按源用例「初态不满足/准备失败记录阻塞」处理为 Blocked。主题发布、接受、消息、已读、互评、摘要、关闭及查询等目标行为不符直接断言失败。断言失败仍发布已提取参数，finally 清理本次实际创建的账号，不能删除来源不明的已有身份。所有变量来自本文件前序响应，社区 ID 不写死。
- 源用例未约定统计落库延迟且未写等待步骤；XSD 不支持请求轮询循环，按 116 同接口先例在两笔评价后插入固定 wait 3000 毫秒再查询摘要，摘要计数不符记为失败（不是阻塞）。
- 消息历史断言不假定排序（接口未定义排序），以 id 匹配两条消息并核对 roomId/senderId/clientMessageId/content/recalled；房间成员用 sorted 对照 A/B。公开评价列表断言各仅一条、hasMore=false，并用 RATING_AB/RATING_BA 与写入响应同一 id 对照。
- finally 顺序清理 B/A：先 GET /me 探测，401/40101 时先 POST /auth/refresh 并 updateParam 更新 TOKEN/REFRESH；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码与 requestId 供清理记录；随后旧/新访问令牌 GET /me 及旧/新 refreshToken POST /auth/refresh 均断言 HTTP 401/code=40101。每步带 ifParameter，单步失败不阻断后续清理；401 不代表账号已删除，仅清理本用例实际创建的用户。
- XML 格式无法表达：清理失败须由调度器停止后续任务（仅以注释声明，单 XML 无法约束跨任务调度）；源用例「执行记录」表格（实际 HTTP/业务码、requestId、结论）由执行方在文档填写，不在任务 XML 内。
- 业务接口缺口：无；源用例引用的邀请接口已被需求三替换，按当前 OpenAPI 的接受接口表达，源用例其余断言均有公开 HTTP 接口支撑。OpenAPI 未声明 GET /me、POST /auth/refresh 的 401 响应，清理核查按源用例清理要求验证真实 HTTP/业务码。
