# TC-013 转换记录

来源：`docs/test-case/013-register-unknown-community.md`。保留社区查询、指定不存在 UUID 的注册负向请求、同身份有效注册、GET /me，以及 finally 注销和原始/最新访问及刷新令牌失效核查。仅生成和离线校验，未运行 HTTP。

负向请求使用 rawBody；断言失败仍保存意外创建账号的 ID/token 并单独清理。负向意外成功将停止 main，因此正常注册不会再次创建同 ID。清理先探测访问令牌，40101 时用本人刷新令牌恢复会话，再注销；每个清理步骤失败仍继续后续步骤。所有凭证提取均敏感标记。

HTTP 失败要求 400/40001，message 非空且不签发令牌。源文档允许已确认契约的 40401；现存契约未确认此替代码，故不宽泛接受。message 是否明确说明社区参数问题仍需结合脱敏响应检查。

## XSD / 执行器缺口

- 单任务 XSD 无法约束共享邮箱的跨任务串行调度，也无法声明清理失败后停止后续任务；执行器必须保证这些约束。
- 无逐用户清理报告及脱敏归档字段；由执行器记录实际 HTTP/业务码、requestId、脱敏响应和清理结论。账号创建但凭证缺失时，不得将清理跳过视作成功，必须记录未确认并停止环境复用。
- `docs/task.xsd` 当前不存在，采用现存 `docs/test-case-xml/task.xsd`。

## HTTP 接口 / 实现缺口

- 没有社区创建 HTTP 接口；空字典时无法补齐前提，XML 明确 Blocked，不将社区查询成功当目标场景通过。源用例指定的负向 UUID 若实际存在也阻塞。
- 当前 `UsersControllerImpl.listCommunities` 返回空列表，运行该实现会阻塞。
- 当前 `AuthControllerImpl.register` 未检查社区存在性，直接使用 communityId 创建用户；环境有可用社区后，负向请求可能意外成功，必须失败并清理，不能降低断言。
