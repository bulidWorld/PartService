# TC-133 转换说明

- 来源：`docs/test-case/133-pagination-limit-0.md`。独立查询社区、注册 A 后，携带 `status=open&limit=0` 调用 GET /topics，要求 HTTP 400、code=40001（limit 仅允许 1…100），不得静默忽略或返回 HTTP 500。
- 步骤1 GET /communities 公开接口，从 data 提取第一项 id → COMMUNITY_A；无社区或 ID 不可取得时 Blocked（公开 HTTP 无社区创建接口）。步骤2 POST /auth/register 使用固定邮箱身份 782213745@qq.com、code=246810、昵称测试用户A、communityId 绑定 COMMUNITY_A；注册断言失败仍提取 user.id/accessToken/refreshToken 及原始凭证副本，供 finally 清理；不能删除来源不明的已有身份。步骤3 目标负向请求：limit=0 低于 OpenAPI minimum=1，经 queryParams 绑定会被校验拒绝，因此改用 rawQuery 写入完整原始查询串 `status=open&limit=0`（不带开头 ?，无空白，XML 中 & 转义为 &amp;），path 属性仍写 OpenAPI 原始路径 /topics；断言真实 HTTP 400、业务码 40001、非空 requestId、data 为空或 {}，等价证明未被静默忽略且非 HTTP 500。
- finally 只清理本用例创建的 USER_A：先 GET /me 探测，401/code=40101 时用 REFRESH_A 刷新并 updateParam 覆盖 TOKEN_A/REFRESH_A；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码及 requestId 用于记录；随后逐一核查原始与最新访问令牌 GET /me、原始与最新刷新令牌 POST /auth/refresh 均 HTTP 401/code=40101。每步 ifParameter 条件保护，单步失败仍继续其他清理；HTTP 401 不视为账号已删除。
- 阻塞/无法表达项：XML 格式无法表达——清理失败须由调度器停止后续任务、共享身份串行复用约定属调度器职责，单 XML 无法表达；真实 HTTP/业务码、requestId、清理结论的执行记录由执行者填写，任务文件不保存令牌原文。业务接口缺口——无，源用例全部断言均基于公开 HTTP 响应。
- 可表达性结论：XSD/导入器可表达本文件全部流程。OpenAPI 未声明 GET /topics 的 400 响应及 40001 业务码，断言按源用例明确期待结果验证真实 HTTP/业务码。
