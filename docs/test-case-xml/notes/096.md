# TC-096 转换说明

- 来源：`docs/test-case/096-chat-wrong-room-recall.md`。生成独立 XML：从本文件 GET /communities 提取 COMMUNITY_A；注册 A（邮箱 782213745@qq.com）、B（手机 13900000002）；A 创建两个主题 T/T2 并分别邀请 B，B 接受后得到 ROOM/ROOM2（断言均为非空 UUID 且互不相同，相同则 Blocked 无法构造错房间前提）；A 在 ROOM 发送消息 M，随后用 ROOM2 撤回 M。
- 目标负向步骤：POST /rooms/{ROOM2}/messages/{M}/recall 断言 HTTP 400 或 404、业务码非 0、requestId 非空、data 仅 null/{}、无额外字段；错误 message 不得包含正文、成员昵称及 USER_A/USER_B ID（参照 092 隐私泄漏核查写法）。源 md 只约定「HTTP 400/404、业务码非 0」未指定具体业务码，故断言 `statusCode in (400, 404) and responseBody["code"] != 0`，越权负向以源用例 md 为准。
- 验证步骤：GET /rooms/{ROOM}/messages?limit=20 断言唯一消息 id=M、recalled 仍为 false、正文不变，证明 URL 中的 roomId 未被忽略；本用例全部预期均可用公开 HTTP 观察，无需末尾 raise Blocked。
- 业务接口缺口：OpenAPI 未声明 recall 的 400/404 响应（仅 200），也未声明 /me、refresh 的 401 响应；XML 按源用例要求断言真实 HTTP/业务码，不改源契约。源码 RoomsControllerImpl.recall 当前只校验发送者、未比对 roomId，实际执行可能返回 200/code=0 并撤回，该偏差会由目标断言如实判为失败，XML 不做实现适配。
- 无社区或注册、主题、邀请、消息准备失败均 Blocked；注册断言失败仍提取 user.id/accessToken/refreshToken（含原始副本），finally 清理本次实际创建的两用户 B、A，不删除来源不明的已有账号。所有变量来自本文件前序响应。
- finally 每用户：GET /me 探测（200/code=0 校验 id 匹配，401/code=40101 则 POST /auth/refresh 并以 updateParam 覆盖当前访问/刷新令牌）→ DELETE /me 断言 200/code=0/data={}/非空 requestId → 原始及当前访问令牌 GET /me、原始及当前刷新令牌 POST /auth/refresh 均断言 401/code=40101。每步带 ifParameter 条件，单步失败不阻断后续；401 不代表账号已删除。
- XSD/导入器可表达本文件全部流程。共享邮箱/手机号须串行执行；单 XML 无法控制跨任务停调度，执行者须记录脱敏实际 HTTP/业务码、requestId、逐用户注销结论，清理失败/未确认时停止环境复用及后续任务。
- 仅生成；未执行 HTTP、部署或数据库操作。已运行 validate.py 离线校验（0 errors）。
