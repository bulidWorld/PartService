## XSD 缺口

- OpenAPI `RegisterRequest.required` 包含 nickname。负向请求必须以 rawBody 绕过必填校验；但 XSD 明确 rawBody 不解析、不插值，并与结构化 body 互斥，因此无法同时遗漏 nickname、将前序 HTTP 社区 ID 动态注入 communityId。硬编码 UUID、字面占位符、同时使用 rawBody/body 均不符合要求。需要增加受控的原始体参数引用能力，或允许显式跳过某些请求 Schema 校验的结构化绑定。
- 不猜测受限 compute 函数白名单，也不在 assertionCode 里修改请求或调用额外 HTTP。
- XSD 没有项目 base_url、跨任务身份串行锁、清理失败停止后续用例、执行记录表及统一脱敏导出的声明。导入项目应配置环境 URL；执行器保证邮箱串行复用、清理失败停环境复用，记录实际 HTTP/业务码、requestId，不能保存验证码或令牌原文。
- 当前 XML 不注册用户，不需要实际 finally。若上述能力补齐，必须将注释中清理要求实现为 finally：预期失败注册意外成功也保存用户及令牌，逐 ID 清理，刷新到期令牌，注销后逐令牌核查失效；不得用凭证失效推断账号删除。

## HTTP 接口/实现缺口

- `UsersControllerImpl.listCommunities()` 当前固定返回空数组；没有公开创建社区接口，无法补齐注册前提。即使以后社区列表非空，仍会因上述 XSD 缺口明确 Blocked。
- 没有公开身份占用预检接口。独立空环境和相同邮箱串行复用由执行者保证，不删除来源不明用户。
- 已查阅 auth.yaml、users.yaml、Requests.Register、AuthControllerImpl 和 UsersControllerImpl；缺昵称必填由契约声明，本文不将未执行行为判为实现缺陷。
