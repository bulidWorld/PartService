# TC-004 邮箱格式错误

- 来源：`docs/test-case/004-invalid-email.md`；输出：`004-invalid-email.xml`。
- 覆盖：独立匿名提交 email / not-an-email / register 验证码请求。断言真实 HTTP 400、整数业务码 40001、响应信封必需字段及非空 requestId，并要求 message 或 data 错误详情指明 identityValue、email 或邮箱字段。使用 rawBody 保留非法邮箱，避免客户端请求 Schema 校验拦截负向测试。
- 准备及清理：由执行者提供源用例要求的独立环境，将项目 base_url 配置为 `http://127.0.0.1:10201/api/v1` 或对应环境地址。无需社区、注册、共享身份或令牌；本用例无账号准备，故无账号删除步骤。
- 未覆盖范围：公开 HTTP 契约没有验证码投递记录或按身份查询用户是否存在的接口，无法从此请求证明“不发送验证码、不创建用户”。不把 HTTP 拒绝响应当作内部副作用已经验证，也不注册或登录以免引入副作用。若服务错误接受请求，不能通过公开接口撤销已发送验证码。
- 契约差异：`src/main/resources/rest-api/auth.yaml` 的 send-code 操作仅声明 200 响应，identityValue 仅声明 string，未约束邮箱格式；XML 保留源用例明确要求的 HTTP 400 / code 40001，不以契约中唯一列出的 200 替换期望。
- XSD 缺口：本用例的可观察 HTTP 范围均可表达，无新增 XSD 需求；上述内部副作用缺少公开观测接口，扩展 XSD 本身不能解决。
- 验证：已用 `/tmp/xml-validation-venv/bin/python` 完成 XSD、断言语法、参数与 OpenAPI 离线校验（0 错误），并通过本机导入器离线转换/配置校验；未运行服务请求，测试执行结论仍为未执行。
