- 来源：`docs/test-case/134-pagination-limit-101.md`。独立查询社区、注册用户 A，GET /topics 携带 limit=101，断言分页上限校验拒绝该请求。
- 步骤 1 GET /communities 提取第一项 id 为 COMMUNITY_A，无社区或 id 不可取得时 Blocked（公开 HTTP 无社区创建接口）。步骤 2 POST /auth/register（identityType=email、identityValue=782213745@qq.com、code=246810、nickname=测试用户A、communityId=COMMUNITY_A）提取 USER_A/TOKEN_A/REFRESH_A 及原始凭证。步骤 3 GET /topics：limit=101 超出 OpenAPI 参数 maximum=100，queryParams 绑定会被请求校验拒绝，故改用 `<rawQuery>status=open&amp;limit=101</rawQuery>` 整体绕过 query 校验，rest 的 path 仍写 OpenAPI 原始路径 /topics；断言 HTTP 400、code=40001、非空 requestId 与非空 message，statusCode==400 同时排除静默忽略（200）与 HTTP 500。
- 无社区或注册准备失败均 Blocked；注册断言失败仍提取 user.id/accessToken/refreshToken，finally 清理本次实际创建的账号，不能删除来源不明的已有身份。所有变量来自本文件前序响应。
- finally 清理 USER_A：先 GET /me 探测，40101 时 POST /auth/refresh 并用 updateParam 更新 TOKEN_A/REFRESH_A；DELETE /me 断言 HTTP 200/code=0/data={} 和非空 requestId，提取业务码及 requestId 用于记录；逐一核查原始及最新访问/刷新凭证 HTTP 401/code=40101。单步失败仍继续后续清理；401 不代表账号已删除。
