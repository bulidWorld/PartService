# TC-136 转换说明

- 来源：`docs/test-case/136-request-invalid-json.md`。唯一负向目标：POST /auth/register 携带非法 JSON `{"identityType":"email",`（截断且末尾逗号），期待 HTTP 400、code=40001、响应仍有 code/message/data/requestId、不暴露堆栈、无业务写入，并以 HTTP 响应和后续查询作为判定依据。
- 目标步骤用 rawBody+CDATA 原样发送非法 JSON，绕过 RegisterRequest 必填校验；/auth/register 声明 application/json，满足 rawBody 前提，无 path/query 绑定。断言验证真实 HTTP 400、业务码 40001（int 非 bool）、四字段存在且 key 不超出信封、requestId/message 非空，并检查 message 与 data 文本不含 exception/traceback/"\tat "/"at com." 等堆栈与异常类型痕迹。
- 无业务写入的后续查询：公开契约没有按身份查询用户存在性的接口，沿用 TC-020 的方式对同一邮箱 POST /auth/login（code=246810），期待 HTTP 401/code=40101/message=身份未注册 且无令牌；若登录被验证码校验先行拦截（HTTP 400/code=40001 且 message 含「验证码」）则 raise Blocked，不声称无写入已验证。
- 非法 JSON 不会注册用户，本用例不创建任何身份，省略 finally 清理；共享邮箱 782213745@qq.com 串行使用，初态由执行环境保障。
- 阻塞/无法表达项：「业务接口缺口」——无公开的身份存在性查询接口，「无业务写入」只能经登录尝试间接验证，被验证码校验拦截时阻塞；「XML 格式无法表达」——无。堆栈不暴露仅能检查常见关键字，无法穷举所有异常输出形态。
- XSD/导入器可表达本文件流程。OpenAPI 未声明 /auth/register 的 400 及 /auth/login 的 401 响应；断言按源用例要求的真实 HTTP/业务码验证。清理失败跨任务停调度无法由单 XML 表达，调度方须串行使用共享身份，清理失败或未确认立即停止环境复用。
- 仅生成；未执行 HTTP、部署或数据库操作。validate.py 的 XSD/语义/OpenAPI 离线校验 0 错误；真实导入器源码树不在本环境，未执行适配器校验。
