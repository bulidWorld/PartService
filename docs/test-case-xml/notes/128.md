# TC-128 转换说明

- 来源：`docs/test-case/128-risk-tag-removal.md`。源用例目标为「不再满足条件时移除系统评级」，头部执行条件即为「阻塞：缺少 HTTP 接口」；仅核查当前可访问的接口，不能验证移除过程及历史保留。
- 逐步骤转换要点：
  - 源用例附加条件及步骤 1 声明没有公开查询窗口规则、重算评级或读取移除历史的 HTTP 接口，无法独立验证移除过程及历史保留。核对全部六个 OpenAPI 文件（auth/users/topics/invitations/rooms/ratings）确认 ratings.yaml 仅有提交评级（POST /topics/{topicId}/ratings）、分类查询（GET /rating-categories）、摘要（GET /me/rating-summary）与列表（GET /users/{userId}/ratings）四个操作，无 risk 相关接口、无删除或修改评价的接口，因此未虚构任何接口。
  - 源用例步骤 2（`GET /rating-categories`）转换为 taskStep 10：公开接口探针，auth mode=none，断言 HTTP 200/code=0、requestId 非空、data 为字符串数组（对应 RatingCategoriesResponse）；探针失败按「准备请求失败」raise Blocked。
  - 源用例步骤 3（以上请求不能完成本场景，缺少 HTTP 能力时记录阻塞，不尝试其他操作）转换为 taskStep 20：复用只读、公开、幂等的 `GET /rating-categories` 作为 Blocked 载体（assertionCode 只允许出现在 rest 步骤内），重复核查响应后 raise Blocked，终态 blocked。按源用例期待结果，查询接口调用成功不能代替目标场景通过，不在任何断言中声称通过。
  - 本用例不注册用户、不提交评价、不创建业务数据，故省略 finally，不执行任何清理。
- 阻塞/无法表达项：
  - 业务接口缺口：源用例目标本身需要查询评级窗口规则、重算评级或读取评级标签移除历史的 HTTP 接口，公开契约没有该能力；`/me/rating-summary` 与 `/users/{userId}/ratings` 只能观察已产生评级的计数与风险标签快照，不能观察「不再满足条件」的判定与移除计算过程。转换以最后一步 raise Blocked 落盘原因，未虚构接口，也未把探针成功记为目标场景通过。
  - XML 格式无法表达：源用例头部元数据（优先级 P1、执行条件「阻塞：缺少 HTTP 接口」、执行记录表格）在 task.xsd 中无对应字段，由 task name 与本文档承载。
- 清理说明：本场景不注册用户、不写入数据，省略 finally 清理；不涉及跨任务「清理失败停止后续任务」的调度要求。
