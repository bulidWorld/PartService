# TC-090 转换说明

- 源为 `docs/test-case/090-chat-outsider-send.md`，同 stem XML 保留独立社区查询、A/B/C 注册、主题、邀请与接受、A 正常消息、C 非成员发送拒绝。每个 REST 显式 auth，检查真实 HTTP 与业务码；注册立即提取用户 ID 和全部凭证，即使断言失败仍纳入清理。
- ROOM 必须为非空 UUID。发送前以成员身份保存聊天室和完整单条消息历史快照；非成员请求检查 HTTP 403/code=40301、无业务 data 或额外响应字段，并检查错误文本不包含原消息、成员昵称或 ID。随后成员查询确认消息快照完全不变、原消息未撤回、消息总数仍一条、成员仍只有 A/B。
- 未覆盖范围：公开 `GET /rooms/{roomId}` 的 Room 无已读位置、最后消息时间字段；`POST /rooms/{roomId}/read` 是写接口，不能作为原状态的无副作用查询。完成可验证断言后明确 raise Blocked，不能将部分结果标为完整通过；此为 HTTP 可观测性缺口，不是 XSD 表达缺口。未验证内部存储、广播或日志。
- OpenAPI 发送接口仅声明 200，未声明源要求的 403/40301；鉴权失败 401 也未充分声明。XML 明确保留所需负向断言，不修改契约或捏造查询接口。
- 当前社区实现返回空数组且没有公开社区创建接口，社区不足时立即 Blocked；不得伪造 ID。准备失败停止后续业务，仍进入 finally。
- finally 按 C/B/A 顺序探测访问凭证，过期时刷新并更新清理凭证；逐个 DELETE /me，检查 HTTP 200/code=0/data={}/requestId，逐个核查原始和当前访问/刷新凭证 HTTP 401/code=40101。单用户清理失败仍尝试其余用户，凭证失效不代表账户已注销。
- 共享邮箱/手机号必须串行；XML 无跨任务锁和清理失败停止调度能力。执行者必须记录脱敏响应、HTTP/业务码、requestId、逐用户清理结论；清理失败或未确认即停止后续任务和环境复用。
- 仅生成并离线校验，未运行 HTTP、部署或修改数据库。`validate.py`：1 XML / 0 errors；`validate_importer.py --importer-root /opt/apps/Deployment/AutoTestService`：1 XML / 0 errors，真实导入器离线转换和配置检查通过。
