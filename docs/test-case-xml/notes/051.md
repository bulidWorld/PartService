# 用例 051 生成说明

- 过期时刻格式：md 要求"当前 UTC 时间加 5 秒（ISO-8601、Z 后缀）"。compute 无带 Z 字面后缀的格式化函数，且本批说明建议的 http_date(RFC1123) 经实测会被本服务端拒绝——Spring Boot 3.5.16 的 Jackson（jackson-datatype-jsr310 2.21.4，本地 m2 已实测）OffsetDateTime 反序列化只接受 ISO-8601，RFC1123 抛出 DateTimeParseException。故 compute 节点设置 timezone="UTC"，用白名单内的 isoformat(add_seconds(now(), 5)) 生成如 2026-10-23T16:30:00+00:00 的 ISO-8601，与"UTC 时刻 + Z 后缀"表示同一时刻（+00:00 偏移而非 Z 后缀），可被服务端解析。格式差异记录于此。
- 真实等待：md 要求"等待直到 expiry 之后至少 2 秒"。expiry=compute 时刻+5 秒，创建主题后固定 wait 7000ms，确保越过过期点至少 2 秒（服务与执行器同机）。
- 昵称：md 要求"测+UUID 去连字符前 12 位"，compute 无 substring/去连字符截取能力 → 改为固定昵称（A=测051甲、B=测051乙）。
- 验证码 code：compute 无随机数字函数 → 固定 "123456"（测试环境已关闭验证码校验）。
- 断言沙箱禁止 re，社区条目 id 的 UUID 格式只断言非空（与 002 样例同风格）。
- 清理：B 的 accept 请求按预期 409 失败，不会产生聊天室，md 清理第 1/5 步"无聊天室则跳过"，故省略 GET /rooms 补录与 chat_room 的 SQL 清理。
