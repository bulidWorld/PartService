# TC-021 有效刷新令牌续期

- 生成 `021-refresh-token.xml`，独立覆盖社区准备、邮箱注册、有效刷新、刷新后 GET /me、全量用户资料一致性、finally 注销及全部注册/刷新签发凭证失效核查。注册立即提取用户 ID、令牌及资料快照；刷新立即更新清理凭证，同时保留新旧令牌。清理先探测访问令牌，40101 时刷新恢复，然后注销；每步清理失败继续其余核查。
- 只生成并离线验证，未请求真实服务。项目 base_url 配为 `http://127.0.0.1:10201/api/v1`；邮箱身份串行复用。
- **HTTP 接口缺口**：当前 `UsersControllerImpl.listCommunities()` 固定返回空数组，且没有社区创建公开接口；实际运行无社区时明确 Blocked，不能算目标刷新场景通过。没有用户总数查询接口，因此“不创建第二个用户”仅能核查刷新响应及后续 /me 均返回注册用户 ID，不能证明内部用户表总数不变。
- **刷新契约**：`auth.yaml` 定义刷新返回 TokenPair，未承诺旧刷新令牌必须立即失效。实现 `AuthControllerImpl.refresh` 调用 `userRepo.issue`，因此不附加新旧 token 必须不同或旧 refresh 立即失效等未承诺断言；全部已签发凭证在注销后核查 401/40101。
- **XSD/执行器缺口**：单任务不能声明跨任务身份互斥、清理失败后禁止后续用例、全局停止环境复用；由调度器实施。请求实际 HTTP/业务码、requestId 应由执行器脱敏记录，不能保存 token 原文。响应丢失/缺失清理凭证时不能把 401 推断为账号注销成功。
- 使用现存 `docs/test-case-xml/task.xsd`（原指定 `docs/task.xsd` 不存在）。断言采用真实执行器支持的四参数入口、Blocked 和内置函数；无动态日期计算需求。
- 离线验证结果：`validate.py docs/test-case-xml/021-refresh-token.xml` 检查 1 个 XML，0 错误；真实执行器 `validate_assertion` 验证全部 13 个断言 AST 通过。
