# TC-011 注册缺少社区

- 来源：`docs/test-case/011-register-missing-community.md`；输出：`011-register-missing-community.xml`。
- 按现存 `docs/test-case-xml/task.xsd` 生成；原引用 `docs/task.xsd` 当前不存在。离线校验通过（1 XML，0 errors），未发送 HTTP，未判定业务通过。
- 保留社区前提查询、缺少 communityId 的原始 JSON 负向注册（HTTP 400/code 40001、消息非空、不签发令牌）、同一邮箱有效参数注册和 GET /me 查询。负向注册意外成功也立即提取用户及两类令牌，断言失败后进入 finally。
- 两次注册分别维护用户及原始/最新令牌，finally 探测访问令牌，遇到 HTTP 401/code 40101 时刷新后注销，核查旧与最新访问/刷新令牌失效。主流程失败停止继续注册，故两组不可能同时成功创建同一用户，不会重复注销同一用户 ID。注销 HTTP 200/code 0/data={} 且 requestId 非空；仅凭 401 不认定注销成功。

## XSD / 执行器缺口

- 单个 task 无跨任务依赖或环境熔断：必须由执行器串行复用邮箱 `782213745@qq.com`，并在任一清理失败或无法确认时停止后续用例；XML 无法直接约束其他任务。
- 没有专门的逐用户清理结果报表及 HTTP 状态提取机制；每个请求断言真实 HTTP/业务码，注销提取业务码和 requestId；执行器需保留脱敏响应及逐请求状态、requestId、结论，禁止保存令牌原文。
- 仅有令牌缺失时不能恢复本次创建用户的清理凭据，需执行器将缺凭据/响应丢失标为清理未确认并停止环境复用。不得将条件跳过解释成清理成功。

## HTTP 接口 / 实现缺口

- `UsersControllerImpl.listCommunities()` 当前固定返回空数组；没有公开社区创建接口。XML 保留前提查询，无社区时明确 Blocked，不会将准备成功视为目标场景通过。依源文档顺序，整个 TC 在此状态下阻塞；缺少社区的负向请求本身不依赖社区，但后续同身份有效注册需要社区。
- 没有公开身份存在性预检接口；必须在独立空测试环境执行，若有效注册出现身份冲突，不删除来源不明的账号。
- OpenAPI 对注册只列出成功响应，未列错误码；本用例 HTTP 400/code 40001 来自源测试要求，不以 40401 放宽缺字段校验（40401 仅适用于另一个“不存在社区”场景）。
